# archive — 과거 허브 배포 스크립트 (실행 금지)

> ⛔ **이 안의 스크립트를 그대로 실행하지 말 것.** 현재 배포는
> [`../deploy-hub.sh`](../deploy-hub.sh) 를 쓴다. 절차 정본: `Vinc-docs vinc/DEPLOYMENT.md §4`.

## 왜 보존하는가

원래 이 파일들은 프로젝트 최상위(**git 리포가 아닌 디렉토리**)에 흩어져 있었다 — 프로덕션을
건드리는 스크립트가 **버전 관리 밖**이라 머신이 죽으면 사라지고 변경 이력도 없었다.
2026-07-21 에 리포 안으로 들여오면서, 실행 가능한 현행 절차(`../deploy-hub.sh`)와
과거 기록을 분리하기 위해 여기에 둔다.

## 왜 실행하면 안 되는가

**두 가지 이유 모두 해당한다:**

1. **특정 과거 커밋에 묶인 일회성 스크립트다.**
   | 파일 | 대상 |
   |---|---|
   | `deploy-sec3.sh` | SEC-3 교차테넌트 쓰기 구멍 봉쇄 (`f8942ed`) |
   | `deploy-hub.sh` | SEC-3 + 웹 Vinc Phase 1 그래프 프록시 (`b5010da`) |
   | `deploy-hub-v040.sh` | 그래프 구조 수리 9건 (`1c26e7c`, 태그 `v0.4.0`) |

2. **빌드 환경 전제가 깨졌다.** 셋 다 `/home/ubuntu/.build-venv` 를 쓰는데, 그 venv 에는
   **kuzu 0.11.3 만 있고 ladybug 가 없다**(실측 2026-07-21). v0.5.3 에서 kuzu 를 완전히
   제거하고 ladybug 단일로 전환했으므로, 지금 이 스크립트를 돌리면 `sidecar.spec` 이
   `collect_all("ladybug")` 에서 실패하거나 확장 번들 누락(G0)으로 막힌다.

## 현행 스크립트가 추가로 하는 것

`../deploy-hub.sh` 는 위 함정들을 없애고, 오늘 실제로 사고를 겪으며 배운 것을 반영했다:

- 빌드 환경을 **매 실행 멱등하게 보장**(ladybug 전용 venv + 확장 시드) — 서버 상태에 의존하지 않음
- **교체 전 격리 스모크**: 새 바이너리를 격리 포트·격리 데이터로 띄워 `/health == "ok"` 확인.
  `--help` 만 보던 옛 방식은 v0.5.1/v0.5.2 가 "스토어를 전혀 못 여는 채" 통과한 원인이었다.
- **실패 시 자동 롤백**: 재시작 후 라이브 `/health` 가 비정상이면 백업 바이너리로 되돌린다.
  ladybug 전용 빌드를 kuzu 데이터 허브에 올려 즉시 장애가 났던 사고(§4.3)를 자동화한 것.
- 미커밋 변경 경고(배포와 git 이 어긋나 "되돌릴 기준점"이 사라지는 문제).

`deploy-hub-v040.sh` 의 **교체 전 무중단 DB 스냅샷**은 좋은 관행이라 현행 스크립트에 승계했다.
