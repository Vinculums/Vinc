## 1. 왜 3D 밖에 이 뷰들이 필요한가

### 1.1 3D 힘-지향이 답하지 못하는 질문

현 Atlas(3d-force-graph, 사이드카 결정론 좌표 소비)는 **조밀도·군집·규모**를 보여준다.
"이 도메인이 얼마나 크고 어디와 엉켜 있는가"에 강하다. 반면 아래 세 질문은
좌표가 의미를 인코딩하지 않는 배치에서는 원리적으로 읽히지 않는다.

| 질문 | 필요한 인코딩 | 현 3D | 새 뷰 |
|---|---|---|---|
| 이 개념은 **무엇을 전제로** 성립했고, 무엇을 낳았는가 | 위치 = 위상 순서(랭크) | ✗ 좌표에 순서 없음 | **흐름** |
| 이 지식은 **언제** 생겼고 그때 무슨 일이 있었는가 | 위치 = 시간 | ✗ `created`/`date` 미투영 | **타임라인** |
| 지식은 **어디서 와서 어디에 쌓이고** 어떤 상태인가 | 두께 = 수량 보존 | ✗ 수량 채널 없음 | **합계** |

참조 이미지 4점은 정확히 이 세 문법의 완성형이다. Physics World(①)는 시간 스파인
좌우로 분류를 흘려보내고, 시각음악 계보도(②)는 레인+역 구조로 계보를 추적하며,
NYT(③)는 좌측 여백 주석으로 각 흐름에 서사를 붙이고, 석유 생키(④)는 **모노크롬만으로**
보존 흐름을 완성한다. ④는 특히 중요하다 — Atlas 의 모노크롬 규율([[vinc.d.atlas-visual-language]] §1.3)을
포기하지 않고도 생키가 성립한다는 증명이기 때문이다.

### 1.2 D34 "Flow Chart 기각"과의 관계 — 충돌하지 않는다

[[vinc.d.atlas-visual-language]] §1.7(D34)은 레이아웃 프리셋 후보 중
`Flow Chart·Scaling Circles·Area Grouping` 을 **"흐름·포함 의미론이 데이터에 없음"**
으로 기각했다. 본 제안은 그 결정을 뒤집지 않는다. 구분점은 셋이다.

1. **층이 다르다.** D34 는 **열린 층(표현 강도)** 의 레이아웃 프리셋 — "좌표는 의미를
   인코딩하지 않는다"가 전제다(§1.7 말미). 본 제안은 좌표가 **의미를 인코딩하는
   별개 Level**(Grid·Matrix 와 같은 계열)이며, 프리셋 목록에 끼어들지 않는다.
2. **의미론이 실제로 존재한다.** 기각 사유였던 "흐름 의미론 부재"는 무방향
   `RELATED_TO` 기준의 판단이었다. 그러나 스키마에는 방향 관계 3종
   (`PREREQUISITE_OF`·`DERIVES_FROM`·`INHERITS_FROM`, `_DIRECTED_RELS`)과
   부착·귀속 관계(`ABOUT`·`ATTACHES_TO`)가 실재하며, 이들만으로 DAG 가 성립한다.
   D34 자신도 `tree`(Ramification, "방향 관계 계층 — 루트 위") 프리셋을 채택했다.
   **흐름 관점은 tree 프리셋의 논리를 전용 렌더러로 승격한 것**이다.
3. **수량은 집계에서 나온다.** 생키의 두께는 개별 개념 노드가 아니라 **집계**
   (도메인별 개념 수, 유입원별 개념 수)에서 보존된다. 합계 관점은 노드 그래프가 아니라
   **집계 흐름도**이므로 "포함 의미론 부재" 지적과 층위가 다르다.

> **DEC 후보 D41** — 본 문서의 채택 여부는 위 3점을 근거로 한 DEC 개정으로 확정한다.
> 기각 시에도 §4 사이드카 투영 2건은 독립 가치가 있다(툴팁 근거 표기·검색 정렬).

## 2. 뷰 3종 명세

> ⚠ **"뷰 3종"은 역사 표현이다**(D53 · 2026-07-26). 흐름(Flow)이 폐기되어 **현행
> 평면 관점은 타임라인·합계 2종**이고, 관점 축 전체는 4종(`3d·2d·timeline·totals`)
> 이다. 코드 권위: `app/src/atlas-prefs.ts:27-29`. §2.1 은 지우지 않고 역사 기록으로
> 남긴다(결정의 근거가 사라지면 재론이 처음부터 다시 시작되기 때문).
>
> **범례 = 엣지 종류 필터(D74)는 지도 관점 한정이다.** 범례가 표시 장치를 넘어
> 엣지 종류 필터가 됐지만, **타임라인은 이 필터에 의도적으로 연동하지 않는다**
> (코드 권위 `app/src/surfaces/atlas.ts:1553-1556`) — 지도(3D·2D)에만 건다.
> 이유: 타임라인 화면에는 범례 컨트롤이 없으므로, 연동하면 **화면에 없는 컨트롤이
> 화면을 조용히 비우는** 일이 생긴다.

세 뷰 모두 **닫힌 층 규율을 그대로 승계**한다 — 모노크롬 잉크 3단, 초점색 1점
(hover/고정 리니지 전용), 타입→형태(원=Concept, 육각=Episode·Record), 크로스도메인은
색이 아닌 형태·농도로 변별.

### 2.1 흐름 (코드 `flow`, 국소·L2 계열)

> ⚠ **이 절은 역사 기록이다 — 흐름 관점은 폐기됐다**(D53 · 발주자 지시 2026-07-26,
> [[vinc.d.atlas-visual-language]] §6 D53). 관점은 5종이 아니라 **4종**
> (`3d·2d·timeline·totals`)이며, 아래 랭크·정렬·두께 규정은 **현행 화면을 설명하지
> 않는다**. 코드 권위: `app/src/atlas-prefs.ts:27-29`(`mountFlow`·`flowDepth`·`깊이`
> 패널 행·카피 4종은 함께 제거됐다).
>
> 폐기 사유: 노드 단위로 훑는 피로가 컸고, 2D 의 `rank` 프리셋(D50)이 같은 위상
> 순서를 무방향 관계까지 포함한 맥락과 함께 보여준다.
>
> **이설 1건 — 관계 근거 패널(D45-V)의 진입점은 이제 2D 선 클릭이다.** 흐름이
> 유일한 입구였으므로 그대로 지웠다면 엣지 `evidence` 를 볼 길이 사라졌을 것이다.

- **질문**: "이 개념은 무엇을 전제하고 무엇을 낳았는가."
- **범위**: 선택 노드의 상·하류 리니지(현 L2 ego 뷰의 방향성 버전) 또는 도메인 렌즈.
- **랭크(x)**: 방향 3종 REL 로 구성한 DAG 의 **longest-path 랭크**. 사이클은 SCC 축약
  후 대표 노드 1개로 접는다(경고 배지). 좌측에 Episode(맥락), 우측에 Record(부착) 을
  고정 열로 둔다 — `ABOUT` 은 항상 좌→우, `ATTACHES_TO` 는 항상 우측 말단.
- **정렬(y)**: 배리센터 2회 스윕(교차 최소화). 결정론 — 난수 없음(D17 정신 승계).
- **엣지 두께**: `confidence` 선형 매핑 `1 + conf*5.5` px. `RELATED_TO` 는 방향이 없으므로
  **1px 실선·저농도**로 배경 처리(랭크에 관여하지 않음).
- **화살촉**: 방향 3종에만. 현 코드의 `_DIRECTED_RELS` 규칙 그대로.
- **인터랙션**: hover → 상·하류 BFS 리니지만 초점색, 나머지 12% 페이드
  (D32 hover 문법 준용). 클릭 = 고정. 더블클릭 = 해당 노드 L2 3D 포커스로 전환.

### 2.2 타임라인 (코드 `timeline`, 도메인/전역)

> ⚠ **이 절의 축 모델은 v0.7.1(2026-08-02)이 대체했다 — 아래 "y=시간 + Episode
> 스파인 + 도메인 레인" 서술은 현행이 아니다.** D62 개정 + D74 lineage 로 다음이
> 확정됐다. 코드 권위: `app/src/surfaces/atlas-planar.ts` `mountTimeline`
> (192-214 · 388-405 행).
>
> | 축·문법 | 현행(v0.7.1) |
> |---|---|
> | 시간축 | **세로 복귀** — 위가 과거, 아래로 내려올수록 현재. **스크롤이 곧 시간**이다 |
> | 가로축 | ~~도메인 레인~~ → **가지(주제)**. 주제 하나 = 가지 하나 |
> | 은유 | **뿌리** — 위에서 아래로 자라며 가지가 갈린다. 진입 시 뿌리 자람 안무 |
> | 원인·결과 | **겹치기(lineage, D74 일부)** — 기본 **꺼짐**. 켜면 계보를 시간축 위에 겹쳐 그리고, **시간을 거스르는 연결은 점선**으로 표기한다 |
> | 버킷 알갱이 | 월 → 연 → 십년 적응(**D72 — 이 부분은 아래 서술이 그대로 유효**) |
>
> **범례 미연동**: 타임라인은 D74 범례=엣지 종류 필터를 따르지 않는다(§2 머리 참조).

- **질문**: "언제 무슨 사건이 어떤 개념을 남겼는가."
- **축**: y = 시간(선형). 중앙 좌측에 **Episode 스파인**(참조 ①의 이벤트 축), 우측에
  **도메인 레인**(참조 ②의 계보 레인). 레인 굵기 = 해당 도메인 활동량(개념+사건 수).
- **마크**: 스파인 틱 = Episode(사건 성격이면 `danger` 토큰으로 표기), 레인 위 원 = Concept(`created`).
- **연결**: 개념 간 방향 REL 은 레인 간 곡선(교차 도메인) 또는 레인 밀착 짧은 호(동일 도메인).
  `ABOUT`(사건→개념)은 **기본 숨김**, hover 시에만 드러난다 — 상시 표시하면 스파게티가 된다.
- **라벨 디클러터**: 1D 최소 간격(에피소드 15px·개념 14px) 밀어내기 + 리더 라인.
  참조 ①이 연도 축에서 쓰는 방식과 동일.
- **월 밴드**: 격월 저농도 밴드로 시간 눈금 대체(격자선 억제).
- **버킷 알갱이 적응 (D72)**: 축이 `content`(내용 시점)로 바뀌면 범위가 세기 단위로
  벌어질 수 있어 월 밴드가 수백 개가 된다. 고유 버킷 수로 알갱이를 고른다 —
  월(고유 월 ≤48) → 연(고유 연 ≤60) → 십년. 키는 각각 `slice(0,7)`·`slice(0,4)`·
  `slice(0,3)+"0"` 이고, 밴드 클릭이 넘기는 구간도 같은 문자열 산술로 만든다
  (`[start, end)` — 파싱 없음). 기록 시점 축은 사실상 항상 월로 떨어지므로
  현행 동작이 그대로 보존된다.

#### 2.3.1 스코프별 모집단 — L2 는 에고(ego) 롤업 (2026-07-24 정밀화)

합계는 본질적으로 **집합을 세는** 뷰라 스코프마다 모집단이 다르다.

| 스코프 | 모집단 | 백엔드 |
|---|---|---|
| L0 | 전체 개념 | `/ledger?owner=` |
| L1(주제) | 그 주제의 개념 | `/ledger?owner=&domain=` |
| **L2(노드)** | **씨앗 주변 개념**(L2 서브그래프와 **같은 depth 2 순회**) | `/ledger?owner=&seed=&depth=2` |

- **문제였던 것**: L2 는 노드 하나에 초점인데, 초기 구현은 그 노드의 **주제 전체**를
  집계해서 크럼("노드 X")과 차트("X의 주제")가 어긋났다. 다른 두 관점(흐름·타임라인)은
  L2 에서 씨앗 기준으로 그려지는데 합계만 한 단계 굵었다.
- **해소(에고 롤업)**: L2 합계의 모집단을 **씨앗의 이웃 개념 집합**으로 정의한다 —
  `_ledger_ego_ids` 가 L2 와 **동일한 `subgraph_ids_plan`(TRAIL 가드, owner 스코프)**
  으로 얻어 두 관점의 모집단이 일치한다. 씨앗 자신 포함. 에피소드/레코드 시드는
  그 시드가 가리키는 개념들이 모집단.
- **연결 상태는 전역**: 구성원의 차수·게이트웨이는 ego 밖으로 나가는 엣지도 센다
  (`ids` 제한은 분류 대상 `c` 에만, 먼 끝 `o` 는 owner 스코프만). "이 개념이 밖과
  얼마나 이어졌나"가 곧 조망 가치라 ego 안으로 가두지 않는다.
- **응답 계약**: `scope`("seed"|"domain"|"all") + `population` 을 가산 투영한다.
  구 사이드카는 `seed` 를 무시하므로 `scope` 키가 없다 — 프론트는 그 부재로 구버전을
  판별해 **주제 롤업으로 우아하게 강등**하고, 캡션도 정직하게 "주제 기준"이라 밝힌다.
- **화면 캡션**(L2 전용, Timeline "날짜 없음" 알약과 같은 자리): 신 사이드카 =
  "이 문서 주변 문서 N개 기준", 구 사이드카 = "이 문서가 속한 주제 전체 기준".
- **보존 불변**: 두 3분할(출처·연결)은 여전히 각각 개념 수로 합해진다 —
  `population` 은 행 합계와 항상 일치. 실엔진 테스트 9건으로 고정(2-소유자 격리·
  ego 밖 게이트웨이·고아 시드·에피소드 시드·구버전 스큐 포함).

#### 2.3.2 리본 배치·병합·강등 (2026-07-28, DEC D68)

외부 연구 입력([[vinc.d.alluvial-research]] — alluvial 정의·교차 최소화·모노크롬
보완책)을 as-built 대조로 걸러 채택한 규칙. 산법은 순수 모듈
`app/src/surfaces/atlas-lodes.ts`(DOM·카피 무지, 결정론), 소비는 `mountTotals`.

- **교차 불변 정리(전제)**: stratum(노드) 순서가 고정이고 주제 노드 안 들어오는
  순서 == 나가는 순서(띠 정합)인 한, lode 재정렬로 교차 **총수**는 줄지 않는다 —
  같은 주제 안 "충돌쌍"(출처 순서와 상태 순서가 반대)은 어느 공통 밴드 순서로도
  좌·우 갭 중 한쪽에서 정확히 1회 교차한다(실측 41 = 41). 종전 (출처,상태) 사전순도
  이미 그 최소치였고 충돌 교차가 전부 오른쪽 갭에 몰렸을 뿐이다. 따라서 배치의
  목표 메트릭은 교차 수가 아니라 **방랑 J = Σ n·((yL−yB)² + (yB−yR)²)** 다(L2 —
  L1 은 밴드가 양끝 사이에 있을 때 평탄해 개선을 못 본다, 연구 부록 A3). 교차 수를
  실제로 줄이는 유일한 지렛대(주제 stratum 재정렬)는 크기순 관례를 깨므로 **부결**
  (발주자 2026-07-28, 시각 검증 후 재론).
- **lode 배치**: barycenter 3라운드(가운데 결합 당김 → 바깥 재동기), keep-best
  (J 가 엄격히 나아진 라운드만 채택 — 전면 동률이면 종전 그림 그대로), 좌표는
  픽셀이 아니라 **개념 단위**(리사이즈가 순서를 재셔플하지 않는다), 동률 비교자는
  종전 의미 순서. 주제 밴드 오프셋은 **튜플당 1개** — 띠 정합이 정렬 규칙 둘의
  일치가 아니라 자료구조로 보장된다(실측 오차 0.000px). 방출 순서(진입 안무 지연·
  DOM 겹침)는 종전 의미 정렬 그대로 — 배치는 y 만 정한다.
- **최소 가닥 두께**: `RIB_MIN` 2px 를 노드 하한(NODE_MIN 5px)과 같은 방식으로
  H 하한(needRib)에 접는다 — 스케일이 전역 선형이라 비례·보존 유지. 절대 캡
  `H_RIB_CAP` 2200px(컨테이너 배수는 강등 판정을 리사이즈 종속으로 만든다).
  캡이 눌러 둔 초과는 종전 1px clamp 가 받친다.
- **기타 병합(Others)**: 주제 알갱이에서 순위 13 이상 **또는** 몫 2% 미만(상위 3
  보호) 주제를 말미 "그 외" stratum 으로 **통병합**(튜플 부분 병합 금지 — 화면에
  남은 주제의 노드 값 무결성). 2개 이상 모일 때만 발동. 기타는 비클릭(열기·드릴다운
  없음, 키 `__others__`), 주변합·보존 불변은 통병합이라 자동 유지. 개념 알갱이는
  대상 아님(전 행 크기 1 — 임계 무의미, 드릴다운 목적 훼손).
- **갭 집계 강등**: 기타 병합 후에도 가닥(튜플×2)이 40 을 넘거나 캡 안에서 전 가닥
  2px 이 불가능하면 리본을 갭별 (출처×주제)+(주제×상태) 합으로 접는다 — 정적 수를
  곱이 아니라 합으로 억제(연구 원문 Stage 2-A). 끝-끝 정체성은 `data-gk` 튜플
  조인이 hover 때 복원 — 반대편 리본은 합이라 통째로 밝는다(수치는 리본 정본값이라
  거짓 없음). 표현이 바뀐 사실은 캡션 한 줄로 고지(조용한 표현 변경 금지, `capped`
  와 같은 규율).
- **개념 알갱이 행 정렬**: 알파벳순 → **(출처, 상태, 제목)**. 행마다 lode 가 1개라
  행 순서가 곧 교차를 결정한다 — 실교차를 줄이는 유일한 지점(발주자 채택
  2026-07-28). 이름 탐색은 검색·목록 표면의 몫.
- **불변 유지**: 주제 stratum 크기순 · 모노크롬 단일 잉크 + 초점 1색 · bklit 치수
  (NODE_W 16 · NODE_PAD 24) · 진입 안무 · `data-tip` 계약 전부 종전 그대로.
  strata 블록은 배경색 헤어라인(.75px)으로 리본 다발에서 도려낸다(리본 테두리와
  같은 "틈" 문법).

## 3. Atlas 통합 설계 (확정)

### 3.1 뷰 전환 UI — 탭이 아니라 `보기` 패널의 관점 행

발주자 지시로 상단 탭 카드를 폐기한다. 스위처는 **이미 있는 인캔버스 `보기` 칩
(`#t-view`) 하나**이며, 그 패널 맨 위에 캡션이 붙은 `.seg` 행 두 개가 들어간다.

```
보기                                     ← 캡션(.hint)
[ 3D | 2D | 흐름 | 타임라인 | 합계 ]      ← 관점(프리퍼런스). 크럼 불변, 패널 닫힘
모든 주제                                 ← 캡션(.hint)
[ Grid | Matrix ]                        ← 범위(Level). 크럼 늘어남, 뒤로가기 성립
깊이 / 라벨 / …                           ← 현재 관점에 유효한 옵션만(VIEW_ROWS)
형태와 포인트 색상은 일관되게 유지됩니다…   ← 닫힌 층 고지(기존 문구 재사용)
```

- **왜 `<select>` 가 아닌가.** 코드베이스는 `<select>` 를 **데이터 바인딩·가변 길이
  목록**에만 쓰고, 고정 열거형(2D/3D·라벨·배치 등)은 전부 `.seg` + `.chip` 을 쓴다.
  관점은 고정 5지선다이므로 네이티브 관용구는 `.seg` 다. **새 CSS 클래스 0개,
  `app.css` 변경 0줄.**
- 툴 행에 흩어져 있던 `#t-grid`·`#t-matrix` 는 **같은 패널의 두 번째 행으로 이동**한다.
  스위처가 두 벌 존재하는 현 상태를 끝낸다.
- 두 행을 캡션으로 갈라 두는 이유: 위 행은 **보는 방식**(스코프 불변), 아래 행은
  **있는 곳**(스코프 변경)이다. 한 줄에 7개를 늘어놓으면 이 차이가 거짓말이 된다.
- 키보드: Tab 으로 칩 진입, Enter/Space 로 커밋, **Esc 로 닫고 포커스는 `보기` 칩 복귀**.
  화살표 이동선택(radiogroup)은 도입하지 않는다 — 이 파일의 다른 `.seg` 여섯 행이
  전부 평범한 버튼이라, 한 행만 다르게 동작하면 같은 모양에 두 거동이 생긴다.
- `aria-expanded`·`hidden`·포커스는 **`openPanel()`/`closePanel()` 두 함수만** 만진다
  (`show()` 가 툴 행을 다시 그리므로 상태 드리프트가 실제 위험이다).

### 3.2 상태 모델 — 관점은 프리퍼런스, 스코프는 트레일

| 축 | 소유 | 저장 | 크럼 |
|---|---|---|---|
| **어디를**(스코프) | `Level` · `trail` | 메모리 + 해시 | `Atlas › 주제 › 노드` |
| **어떻게**(관점) | `AtlasPrefs.view` | `localStorage` | 평면 관점일 때만 비클릭 꼬리 칩 |

- `Level` 유니온 변경은 **`l2` 에 `domain?` 추가 한 줄뿐**. 새 variant 를 만들지 않으므로
  `show()` 분기·크럼 렌더가 그대로 산다.
- 관점 전환은 트레일을 밀거나 자르지 않는다. 범위(Grid·Matrix) 전환만 프레임을 민다.
- 관점 커밋 시 현재 위치가 `compare`/`grid`/`matrix` 면 **가장 가까운 l0/l1/l2 로 되돌린다**
  (평면 관점은 "장소"가 아니라 "보는 방식"이므로 프레임 위에 겹칠 수 없다).
- 스코프 계승: 평면 관점은 자체 스코프 상태를 갖지 않고 `trail` 끝을 읽는다.
  L0=전체, L1=그 주제, L2=그 노드 ego.
  > **as-built 정합(2026-07-25, DEC D46-S).** "L0=전체"는 합계만 지키고 있었다 —
  > 흐름은 주제 ties 를, 타임라인은 "주제에는 날짜가 없다" 빈 화면을 냈다(둘 다
  > `/atlas` 주제 집계를 불렀기 때문). 이제 셋 다 전량이다: 흐름·타임라인이
  > `/graph?owner=`(도메인·씨앗 없음)를 부른다. **3D·2D 의 L0 는 주제 층(Domain
  > Atlas, D16) 그대로** — "지도는 조망, 평면은 전량"으로 역할이 갈린다.

## 4. 선행 과제 — 사이드카 투영 2건

현재 `api/query.py` `shape_graph` 는 엣지에 `source/target/type/cross_domain/role` 만,
노드에 `id/label/domain/kind/degree/props/tags` 만 싣는다. 두 채널이 빠져 있다.

| # | 결손 | DB 실재 | 필요 뷰 | 조치 |
|---|---|---|---|---|
| P1 | 엣지 `confidence`(+`evidence`) | `_EVIDENCE_RELS` 5종에 `confidence DOUBLE`·`evidence STRING` | 흐름 두께·툴팁 근거 | `shape_graph` 엣지 dict 에 두 필드 추가(없으면 키 자체를 생략 — `role` 과 동형) |
| P2 | 노드 타임스탬프 | `Episode.date`·`Concept.created`·`Record.created`, 폴백 `updated_at` | 타임라인 시간축 | 동일 함수에서 `ts` 단일 필드로 정규화 투영 |
| P3 | 집계 롤업 | 없음(신설) | 합계 | `GET /ledger` 신설 + `_PROXY_OPS` 등재 |
| P4 | 노드 **내용 시점** + 문서 최초 기록 시각 | 없음(스키마 v7 신설 — D72) | 타임라인 축 전환 | `Concept·Record.content_time` · `_DocMeta.created_at/content_time` + `content_ts` 투영 + `/graph`·`/docs-in-range` 의 `basis` |

- 넷 다 **가산적 변경**(기존 필드 불변) → 프론트 하위호환. `GraphEdge`/`GraphNode`
  타입에 선택 필드로 추가. P1~P3 은 마이그레이션 불필요(스키마 v3 그대로, 투영만
  확장), P4 만 스키마 v7 열 추가를 동반한다.
- **투영 확대는 화이트리스트 플랜에만 한정한다** — `graph_plan` ·
  `graph_rows_for_ids_plan` · `episode_rows_plan`(+ P4 부터 `record_rows_plan`).
  `bridge_rows_plan`·`entity_rows_for_ids_plan` 에 `r.evidence` 를 붙이면 해당 REL
  테이블에 그 열이 없어 **Binder 오류**가 나고, 새 뷰가 아니라 **모든 레벨의
  `/graph` 가 죽는다**. 배포 전 플랜 실행 테스트로 못 박는다.
  - ⚠ **플랜별로 허용 열이 다르다.** P1 의 `evidence`/`confidence` 는 *관계* 열이라
    위 셋뿐이고, P4 의 `content_time` 은 *노드* 열이라 그 열을 실제로 얻은 라벨의
    플랜에서만 쓸 수 있다: `Concept`(graph·rows_for_ids) · `Record`(record_rows) 는
    가능, `Episode`·`Bridge`·`Entity` 는 열이 없으므로 **상수 `'' AS content_ts`**
    로 자리만 맞춘다. "P4 니까 record 도 되겠지"를 evidence 에 적용하면 그 즉시
    같은 크래시다 — 열의 소재를 라벨 단위로 확인하고 붙인다.

**`basis` 계약 (D72).** 시간축은 두 갈래다: `recorded`(기본 — 현행 `ts`,
`coalesce(created, updated_at)`) 와 `content`(문서 내용이 가리키는 시점).

- `/graph?basis=` 는 **셰이핑 이후 파이썬에서** 스왑한다(Cypher 분기 추가 금지 —
  플랜 수가 늘수록 위 함정 표면이 넓어진다). 노드는 `ts` 와 `content_ts` 를 **둘 다**
  싣고 내려가므로, 프론트의 축 전환은 **재요청 없이** 성립한다.
- `/docs-in-range?basis=` 는 **차트와 문자 그대로 같은 기준**이어야 한다. 밴드를
  눌러 여는 목록이 다른 시간 열로 세면 화면이 스스로를 반박한다(기존 주석
  `query.py` `docs_in_range` 의 캐비앳과 동일한 이유). 양쪽 모두 응답에 `basis` 를
  **에코**해 화면이 무엇을 셌는지 밝힌다.
- `content_time` 은 자유 문자열이되 `YYYY[-MM[-DD]]` **접두 검증 통과분만** 저장한다
  (불합격은 빈 값 — 조용한 폐기가 아니라 편집기가 힌트를 띄운다). 비교·버킷은
  전부 **문자열 사전식**이다(날짜 파싱 도입 금지 — `ts` 계약과 동형, 혼합 정밀도
  `"1905" < "1905-06"` 가 자연 정렬된다). 기원전·음수 연도는 미지원.
- 값이 없는 노드는 내용 축에서 **빠진다**(0 이나 오늘로 채우지 않는다). 캡션이
  몇 개가 빠졌는지 밝힌다.
- **버전 스큐**: 구 사이드카 + 신 앱이면 `content_ts` 자체가 없다 — 내용 축은 빈
  상태 카피로 강등하고 크래시하지 않는다(P1~P3 과 동일한 강등 규율).
- `/ledger` 는 개념 단위 두 플랜(출처·연결)을 뽑아 **파이썬에서 폴드**한다. 고아 판정을
  네이티브 `algo` 확장(`component_diagnosis`)에 맡기지 않는 이유는, 오프라인 번들에서
  그 확장이 `executed:false` 로 물러나기 때문이다 — 원장은 항상 그려져야 한다.
- **테넌시(SEC-1) 하드 룰**: `owner` 필수, 모든 엣지 패턴의 **양 끝**을 `owner_id` 로 건다.
  `Bridge` 만 예외로 `(b.owner_id = $owner OR b.owner_id = '')` — 구버전 로컬 사용자의
  브리지 결합이 조용히 사라지는 것을 막기 위함이다. 호스티드에서는 프록시가 서명된
  `sub` 로 owner 를 덮어쓰고 클라이언트 값은 버린다.
- **버전 스큐**: 구 사이드카에 새 앱이 붙으면 `/ledger` 404 · `ts` 없음 · `confidence` 없음.
  배포는 **백엔드 먼저**(DB→코드 순서 정책과 동형), 프론트는 셋 다 없을 때의 빈 상태를
  authored copy 로 처리한다(§7 상당).

## 5. 색상 정책 — 도메인 채색을 도입하지 않는 정량 근거

홈페이지에는 `--dom-1..6` 카테고리 팔레트가 이미 있고(`Vinc-homepage/site/assets/site.css`),
새 뷰에서 도메인별 채색에 재사용하고 싶은 유혹이 있다. **검증기 실측 결과 부적격이다.**

| 모드 | 대비(≥3:1) | 인접쌍 CVD ΔE(≥8) | 정상시야 ΔE(≥15) | 판정 |
|---|---|---|---|---|
| 라이트(surface `#F2F2F0`) | PASS | **5.8** (`#A03A3A`↔`#8A6A1F`, deutan) | **12.7** | FAIL |
| 다크(surface `#0C0D13`) | PASS | **0.8** (`#C29FD9`↔`#7FBCD9`, deutan) | **11.0** | FAIL |

다크 인접쌍 ΔE 0.8 은 적록색약 사용자에게 **사실상 동일색**이다. 홈페이지 도메인
분포 막대(항목 수 적고 직접 라벨 동반)에서는 완충되지만, 리본 수십 개가 교차하는
생키에서는 완충 장치가 없다.

**결론**: 새 뷰도 모노크롬 잉크 + 초점색 1점을 유지한다(D31 닫힌 층 그대로).
변별은 **위치(랭크·레인)·두께·형태·직접 라벨**이 담당한다 — 참조 ④가 증명한 경로다.
채색이 꼭 필요해지면 그때 팔레트를 **재설계**(검증기 통과)해서 별도 DEC 로 올린다.

**교정한 실패 3건(구현 시 반복 주의).**

1. **숨겨진 탭에서 `getBBox()` 는 0을 반환한다.** 세 뷰를 즉시 빌드했더니 합계 뷰
   라벨 판 폭이 19px(=패딩만)로 계산됐다. → 보일 때 그리는 지연 빌드로 전환.
   Grid·Matrix 를 숨긴 채 미리 그리는 코드가 생기면 동일 함정에 빠진다.
2. **시간축 밀집 구간의 라벨은 반드시 디클러터가 필요하다.** 7월 구간 에피소드
   4건이 7.2px 간격으로 겹쳤다 → 최소 간격 밀어내기 + 리더 라인으로 해소.
3. **패널을 다시 그리면 바깥 클릭 판정이 깨진다.** 옵션 칩을 누르면 패널을 재렌더하므로,
   버블 시점에는 눌린 칩이 이미 DOM 에서 떨어져 나가 "바깥 클릭"으로 오인되어 패널이
   닫혔다 → **캡처 단계에서 판정**. 앱 구현도 같은 순서 문제를 안는다.

**집계는 개념 단위에서 파생시킨다.** 시안 초판은 롤업 수치를 상수로 박아 두었는데,
"고아 숨김" 같은 필터를 걸면 열 합계 보존이 깨졌다. 개념 한 건씩 출처(에피소드 유래 >
레코드 부착 > 직접 생성 우선순위)와 상태(고아/게이트웨이/연결)를 판정해 접는 방식으로
바꾸자 어떤 필터에서도 보존이 성립한다. **사이드카 `/ledger` 폴드도 같은 구조여야 한다.**

| **T1** | `graph_plan` 의 `OPTIONAL MATCH (c)-[r]->(d:Concept)` 가 **먼 끝(d)을 owner 로 걸지 않았다** | 형제 플랜(`graph_rows_for_ids_plan`)은 이미 걸고 있었다. 여기에 `evidence`·`confidence`·`target_ts` 를 새로 투영하면서, 남의 근거 문장이 흐름 뷰 툴팁까지 도달했다. **SEC-1 재발**. 2-소유자 실엔진 테스트로 고정 |
| **T2** | 원장 출처 3분류가 **분할(partition)이 아니었다** | 에피소드와 레코드를 둘 다 가진 개념이 양쪽에 계수되어 합계가 부풀었다. `episodic > record > 직접` 우선순위로 배타 분류 |
| **T3** | 축 플랜(episode/record/bridge)이 **대상 개념의 `ts` 를 투영하지 않았다** | 에피소드로 진입한 L2(`#atlas/trace/episode:x`)에서 모든 개념이 "날짜 없음"이 되어, 날짜가 다 있는데도 타임라인이 빈 상태를 그렸다. 투영 추가 + `shape_graph` 중복제거가 **빈 ts 를 나중 행으로 승격**하도록 수정 |
| **T4** | 링크 플랜 실패를 **성공으로 보고**했다 | 두 번째 쿼리가 degrade 하면 전원이 고아로 집계되는데 응답은 `executed:true`. 원장은 "조용히 틀리기"가 가장 나쁘다 |
| **T5** | 프레임(Grid·Matrix·Compare)에서 **화면이 그리지 않는 관점을 UI 가 주장**했다 | 칩은 `보기 · 흐름`, 크럼엔 흐름 꼬리, 패널엔 흐름과 Grid 가 동시 활성인데 화면은 3D 미니였다. `shownView(level)` 단일 진실원으로 해소 |
| **T6** | **아무 것도 하지 않는 옵션 행**이 노출됐다 | 관점 기준으로만 행을 골라, 그 레벨의 렌더러가 읽지도 않는 옵션이 떴다. 행 목록은 **렌더러가 실제로 읽는 값**에서 파생해야 한다 |
