## 1. 시각 언어 — 마크 사양 (Mark Spec)

### 1.1 노드 — 형태(타입)·크기(중요도)·상태(점 표기)·깊이(2.5D)

**형태 = 타입** (Notation 아이콘 세트와 동형 — 육각=그래프, 점=레코드):

| 노드 타입 | 형태 | 근거 |
|---|---|---|
| Concept | **육각형** (hexagon) | 그래프의 1급 시민 — Notation 세트의 그래프 표기 승계 |
| Episode/Record | **원** (circle) | 낱개 레코드 — 점 3단계 표기와 동족 |
| Bridge | **마름모** (diamond) | 두 도메인 사이에 "끼어 있는" 구조물 — 방향 중립 |
| Domain (L0 슈퍼노드) | **이중 육각** (hexagon + 외곽 헤어라인 링) | 육각의 집합임을 자기 표현 |
| 게이트웨이(렌즈 경계) | 원 타입 형태 유지 + **반투명 잉크 + 파선 외곽** | "여기 있지만 여기 소속이 아님" |

**크기 = 스코프 내 중요도** — 단일 변수 원칙(이중 인코딩 금지):
- L0: `8 + 3·√(records)` — 도메인 레코드 수.
- L1/L2: `4 + 2·√(degree)`, **상한 18px** — 연결도. 검색 score·pin 은 크기에 싣지
  않는다(§4·§1.3 의 별도 채널).
- 최소 가독 하한 4px. 크기 스케일은 √(제곱근) 고정 — 선형은 허브가 화면을 삼킨다.

**상태 = 점 표기** (색 금지): 노드 우상단 위성 점 `dot-filled`(확정/pin) ·
`dot-half`(작업 중) · `dot-empty`(후보/미검증). 수입(shared-in) 노드는 `⇣` 표기
1회기 badge(§5.3).

**깊이 — 전면 3D 채택 (D21 개정, 발주자 확정 2026-07-10).** 본 문서 v0.1 은
2.5D 를 권고했으나 **발주자 결정으로 전면 3D 그래프를 채택**한다. 형태=타입
규정은 3D 프리미티브로 승격된다:

| 노드 타입 | 3D 형태 | 비고 |
|---|---|---|
| Concept | ~~육각기둥~~ → **구**(sphere) — **D35 개정** | 최다 노드종에 최소 잉크 형태(발주자: "시각적으로 비대" → 완화) |
| Episode/Record | ~~구~~ → **작은 정육각기둥**(변=높이 — 전 모서리 등길이) — **D35 개정** | 육각 시그니처를 희소한 기록물로 이관 |
| Bridge | **정팔면체**(octahedron) | 마름모의 입체화(유지) |
| Domain (L0) | ~~대형 육각기둥 + 외곽 링~~ → **구 + 적도 원형 링**(토성형) — **D35 개정** | 개념(구)의 상위 집합임을 링으로 자기 표현 |
| 게이트웨이 | 원 타입 형태 + 반투명(opacity ≈0.45) | |

**모노크롬 3D 규율**: 입체는 색이 아니라 **음영과 대기**로 만든다 — 무광 잉크
재질(Lambert, `ink`/`ink_soft`/`ink_mute` 3단), 배경·안개(fog) = `paper`(원경이
종이로 잦아듦), 조명은 무채 앰비언트+디렉셔널 1개, 포인트색은 §1.3 그대로
"지금의 초점"(seed·검색 착지·수입 점등) 전용. 순검정 그림자 금지 유지.

**3D 조작·단서**: 궤도(orbit) 카메라(감쇠 포함, 자동 회전 없음), 클릭 = 카메라
fly-to, hover = 이웃 유지·비이웃 후퇴(재질 투명도), 안개가 깊이 원근을 담당.
렌더러 = three.js 계열 3d-force-graph(MIT — 라이선스 게이트 적합), Sigma 는
Compare 좌우 렌즈(2D 평면 비교가 목적인 뷰)에 잔존한다. 레이아웃 좌표는 사이드카
결정론 계산(D17)이 **z 축으로 확장**된다.

### 1.2 엣지 — 형태 = 관계 의미

색이 아니라 **선의 형태·무게·머리**로 관계 타입을 변별한다:

| 관계 | 선 | 방향 표기 |
|---|---|---|
| relates_to | 실선 헤어라인 (`--border`) | 없음(대칭) |
| prerequisite_of | 실선 + **닫힌 화살촉** | A ▶ B (A 가 먼저) |
| derives_from | 실선 + **열린 화살촉** | 파생 방향 |
| inherits_from | **이중선**(평행 2획) | 상속 방향 화살촉 |
| 크로스도메인(모든 타입) | 위 형태 유지 + **파선(dashed)** + 중점에 양끝 도메인 아이콘 페어 | — |
| Bridge 매개(CONNECTS) | **점선(dotted)** — 직접 연결이 아닌 매개임을 파선과 구별 | 없음 |

- ~~굵기 = 가중치(L0 결합 수 log 스케일)~~ → **(D33 개정) 농도 = 가중치**:
  3D 렌더러에서 굵기(linkWidth)는 원통 튜브 메시를 만들어 "뚱뚱한 반투명 튜브"가
  된다(발주자 지적, 실렌더 확인). 전 엣지 헤어라인(THREE.Line) 고정, 가중치는
  잉크 농도 3단(#38332a/#6f6754/#8d8574)으로. L1/L2 균일 원칙은 유지.
- 색: 전 엣지 잉크 계열 안에서만. 무가중 크로스도메인 = 저농도(#b3a992 —
  구 "세선"의 등가, D33). 포인트색은 엣지에 쓰지 않는다(포인트는 §1.3 예약).
- ~~곡률: 평행 다중 엣지만 미세 곡선, 기본 직선~~ → **(D33 개정) 기본 곡률
  0.18**: 3D 밀집 그래프에서 직선은 노드 관통·중첩으로 뭉개진다 — 완만한 곡선이
  선을 갈라 "부드럽고 명확한" 연결로 읽힌다.
- 구현 주: 3D 전환(D21)으로 Sigma `EdgeProgram` 항목은 소멸. 파선(크로스)·
  점선(Bridge 매개)·이중선(inherits)은 3d-force-graph 헤어라인에서 후속
  (Line dash 재질 델타) — 현재는 농도·화살촉으로 변별.
- **발선 = 노드 중심 유지(D33 보강, 발주자 문답)**: 꼭지점/포트(송·수신 위성 점)
  발선은 기각 — 포트 문법은 "2D 고정 방향 + 흐름 의미론 + 연결 소수"에서 성립
  하는데 우리는 3D 궤도 회전 + 대칭 관계 다수 + 허브 연결 수십이다. 불투명
  메시가 내부 구간을 가려 중심 발선은 이미 표면 발선으로 읽힌다. 대신 실익
  두 가지를 흡수: ① **화살촉 = 도착 노드 표면 바로 밖**(도착 반경+여백 기반
  동적 relPos — 고정 94% 는 허브 메시 안에 파묻힘) ② 상세 레일이 방향 관계를
  `→ n out · ← n in` 으로 분리 표기(포트의 정보를 조사 시점에만, 상태=표기).

### 1.3 단일 포인트색의 예약 용도

딥 잉크블루(`--point`)는 화면당 1의미 원칙: Atlas 에서는 **"지금의 초점"**(L2 seed ·
검색 착지 노드 · 수입 직후 하이라이트)에만 쓴다. CTA 버튼과 의미가 같다 —
"시선이 놓일 곳".

### 1.4 라벨

### 1.5 표현 강도 커스터마이징 — 열린 층과 닫힌 층 (D31)

사용자 커스터마이징은 두 층으로 나눈다. **의미를 인코딩하는 채널은 스펙이
소유하고, "얼마나 진하게 보여줄까"는 사용자가 소유한다.** 임의 색/형태 변경을
열면 공유 팩([[vinc.c.sharepack]])을 받은 상대와 "같은 그림"을 못 보게 되어
시각 언어(D20·D22)가 무너진다 — 닫힌 층이 존재하는 이유.

| 층 | 항목 | 소유 |
|---|---|---|
| **열린 층(표현 강도)** | 뷰 차원 **3D ↔ 2D**(z 평면화 — 좌표는 동일 사이드카 정본, D17 유지) · 노드 크기 스케일(연결수 √ ↔ 균일) · 라벨 밀도(hover ↔ 없음) · 방향 화살촉 표시 여부 · 산개(spread) 배율 · 고아 표시(D32) · **레이아웃 프리셋(D34, §1.7)** | 사용자 — 인캔버스 `View` 패널, `localStorage` 지속 |
| **닫힌 층(의미 매핑)** | 타입→형태(§1.1 프리미티브 표) · 포인트색=초점 전용(§1.3) · 크로스도메인=세선/ink_mute(§1.2) · 모노크롬 잉크 3단 | 스펙 — 변경은 DEC 개정으로만 |

- 2D 모드는 **동일 렌더러의 z 평면화**다(별도 2D 엔진 아님): fz=0 + 정면 카메라 +
  회전 잠금(팬/줌만). 프리미티브는 카메라를 향해 눕혀 형태=타입 판독을 유지한다
  (육각기둥 → 육각 면이 정면). Compare/Multiples 는 원래 의도적 평면(D22)이라
  토글 대상이 아니다.
- 컨트롤 위치는 Atlas 캔버스 안(인캔버스 — [[vinc.d.desktop-shell]] §1 의
  Obsidian 관례 채택과 동일 근거). 사이드카 계약 변경 없음.

### 1.6 허브·고아·집중 — MOC 구조 규율 (D32)

발주자 3원칙(2026-07-10): ① 허브 중심 구조(굵직한 허브 + 위성) ② 고아 노드
최소화(잇거나 필터) ③ hover 시 강한 페이드로 집중.

- **허브 승격 서열**: 클러스터 중심은 `(pinned DESC, degree DESC, id)` 순 —
  **pin 이 연결수보다 우선**한다(사용자가 확정한 노드가 지도의 기준점).
  레이아웃(`layout_positions`)과 크기(pin ×1.25) 양쪽에 반영. Concept 의
  pinned 열은 P4 스키마 델타(현재는 Episode 만 보유 — 기제·테스트는 선행 구현).
- **고아 최소화 2동선**: ⓐ 필터 — View 패널 `Unlinked show/hide`(열린 층,
  초점 노드는 항상 유지) ⓑ 잇기 — 상세 레일이 연결 0 노드에 `possible ties`
  후보를 제시(`GET /suggest-ties`: 태그 교집합 +2·같은 도메인 +1, 기연결 제외,
  결정론 순 — D25 임베딩 유사도의 **전 단계** 근사), `Bind` 확정은 fragment
  MERGE(`POST /ingest/fragment`) 경유로 단일 쓰기 표면(R4) 유지.
- **hover 집중**: 이징 페이드(스냅 금지) + 색이 아닌 농도로 집중을 만든다
  (모노크롬 규율 유지). **물러남 수치는 아래 표가 정본**(D32 개정 2026-07-25).
- **L2 딥링크**: `#atlas/trace/<id>` — 검색/외부에서 노드 포커스로 직행.

**물러남(recede) 수치 — 정본 (D32 개정, 발주자 확정 2026-07-25)**

초점을 잃은 마크가 내려앉는 **불투명도 하한**이다. 전 관점(3D·2D·흐름·타임라인·
합계)과 전 표면이 같은 값을 쓴다 — 뷰마다 다른 수치는 드리프트로 간주한다.
근거는 [[vinc.d.motion-research]] §4-4(bklit 생키 검증값 0.4/0.1)이며, 선은
Vinc 의 기존 12% 를 유지해 한 단계 더 물러난다.

| 대상 | 값 | 비고 |
|---|---|---|
| 비이웃 **노드**(마크·구·점·생키 노드) | **0.40** | 구 12% 개정 — 주변 지도는 맥락으로 읽히게 남긴다 |
| 비인접 **선**(엣지·링크·레인) | **0.12** | 시각 소음의 주범이라 노드보다 더 내린다 |
| 딸린 **텍스트**(라벨·수치) | **0.35** | 노드보다 살짝 아래 — 글자는 잔상이 강하다 |

- 값은 **토큰으로만** 참조한다(`recede.node`·`recede.line`·`recede.text`).
  뷰 코드에 숫자 리터럴 금지 — 색 하드코딩 금지와 같은 규율.
- 3D 는 재질 불투명도에 곱(`base × recede`), 평면은 SVG opacity 에 직접 적용.
  3D 엣지의 색 스왑(`pal.link.fade`) 도 같은 값의 농도 전이로 통일한다.
- 초점 자신과 그 이웃(생키는 hover 링크의 양 끝)은 **감쇠 없음**(1.0).
- `prefers-reduced-motion` 에서도 **값은 그대로** — 사라지는 것은 전이(이징)뿐이다.

### 1.7 레이아웃 프리셋 (D34 → **D51 → D74**)

> ⚠ **현행은 2종이다**(D74, v0.7.1 · 2026-08-02). 아래 5종 표는 **역사 기록**이며
> 지금의 화면을 설명하지 않는다. 코드 권위: `app/src/atlas-prefs.ts`
> `AtlasLayout = "hub" | "rank"`.
>
> | 현행 프리셋 | 계열 | 배치 규칙 |
> |---|---|---|
> | `hub`(중심순, 기본) | 중심 | 뿌리(공통 도메인)가 원점, 주제가 사방으로, 그 주제 방향으로 하위 개념이 다시 퍼진다. 중심성은 버리지 않고 **가지 안으로** 옮겼다(한 주제 안에서 연결이 많을수록 축·뿌리에 가깝다) |
> | `rank`(순서순) | 순서 | 층(x)=전역 위상 순서. 도메인으로 클러스터를 만들지 않되 **열 안 순서**를 도메인 띠로 묶고, 3D 는 z 에 도메인 슬랩을 준다 |
>
> 좌표는 **두 벌**이다: `x`/`y`/`z` = 3D 정본, `x2`/`y2` = 2D 정본. 2D 는 3D 를
> 투영한 것이 아니다 — z 를 눌러 평탄화하면 서로 다른 노드가 같은 점이 되어 하나가
> 사라진다. 구 사이드카에는 `x2`/`y2` 가 없어 `x`/`y` 로 우아하게 강등한다.
>
> 폐기된 6종(`shell`·`radial`·`circle`·`tree`·`organic`·`dendro`)은 이 둘의 변주라
> 고를 이유가 없었다. 저장된 옛 이름은 `LAYOUT_ALIAS` 가 `hub` 로 조용히 접어
> 딥링크가 깨지지 않는다. 정정본: `record:fact-atlas-layout-presets`(그래프).

**(이하 역사 기록 — 2026-07-10 D34 원안)** 발주자 요청(시각화 분류표 이미지 기반):
그래프 배치 형식을 사용자가 고른다. 좌표는 계속 **사이드카가 결정론 산출**(D17 유지,
이 조항만은 D74 에서도 불변) — `GET /graph?layout=` 프리셋 5종, 전부 순수 함수:

| 프리셋 | 분류표 대응 | 배치 규칙 |
|---|---|---|
| `shell`(당시 기본) | Sphere | fibonacci 구면 산개, 허브 중심 |
| `radial` | Centralized Burst | 허브(pin>degree) 중심, BFS 깊이 = 동심 껍질(반경은 껍질 노드 수에 적응 — 둘레 간격 ≥ 노드 지름), 고아 = 최외곽 |
| `circle` | Circular Ties | 원둘레 정렬, 엣지 = 현(chord) |
| `tree` | Ramification | 방향 관계(prerequisite/derives/inherits) 계층 — 루트 위, 미관여 노드 최하단 |
| `organic` | Organic Rhizome | 결정론 힘-지향(척력 1/d²+스프링, 60 반복) — 80분위 반경 정규화(최외곽 고아가 본체를 압축시키지 않게) |
| — 기각 | Flow Chart·Scaling Circles·Area Grouping | 흐름·포함 의미론이 데이터에 없음. Arc Diagram 은 2D 전용 후순위 |

선택 UI 는 View 패널 `Layout` 행(열린 층 — 좌표는 의미를 인코딩하지 않는다).
Multiples 그리드는 **카드별 오버라이드**(`↻` 사이클 칩) — "도메인마다 다른
형식으로 나눠 보기"가 한 화면에서 성립.

## 3. 멀티 도메인 뷰 — 나눠 보기와 개념 결합

> ⚠ **이 절 전체는 역사 기록이다 — 2026-08-02 발주자 지시로 프레임 3종
> (Grid/Multiples · Matrix · Compare)이 전부 화면에서 제거됐다.** 코드 권위:
> `app/src/surfaces/atlas.ts:40-43`. 아래 3.1~3.3 규정은 **지금의 화면을 설명하지
> 않는다**.
>
> - `Grid`·`Matrix` 칩(D43 이 `보기` 패널 범위 행으로 옮겼던 것)은 패널에서 함께
>   사라졌다. 남은 축은 관점(3D·2D·타임라인·합계)과 스코프(L0·L1·L2) 둘뿐이다.
> - **Compare 딥링크 `#atlas/compare/a/b` 는 L0 으로 접힌다**(`atlas.ts:1668-1672`)
>   — 오래된 공유 링크가 404 나 빈 화면이 아니라 지도 첫 화면에 착지한다.
> - 되살리려면 **새 진입점 설계가 선행된다**. 옛 진입점(L0 툴바 토글·결합 엣지
>   클릭·Multiples 카드 2선택)은 더 이상 존재하지 않으므로, 규정만 복원하면 갈 수
>   없는 화면이 문서에만 산다.
> - 규정 자체(소면적 다중 vs 오버레이 근거, `/coupling` 계약, 결합 레일 문법)는
>   지우지 않는다 — 재도입 시 다시 설계할 이유가 없는 부분이다.

연구 근거: 다중 네트워크 비교는 **소면적 다중(small multiples)** 이 패턴·이상치
비교에 강하고, **오버레이**는 3개 초과 시 급격히 붕괴한다(다층 네트워크 시각화
서베이·동적 네트워크 비교 연구, 2026-07 조사). 따라서 3뷰 체계로 규정한다:

### 3.1 Multiples 뷰 — "각각마다 나누어서"

- 진입: L0 툴바 `Grid` 토글.
- 도메인당 미니 캔버스(레이아웃 좌표 재사용 — 재계산 없음)를 카드 그리드로.
  카드 헤더 = 도메인명 + 레코드 수 + 결합 수(`bar` 표기).
- **동기화**: hover 한 개념의 크로스도메인 상대가 다른 카드에서 동시 점등(brushing
  & linking). 카드 클릭 = 그 도메인 L1 로 확대.
- 카드 수 상한 9(3×3) — 초과 시 레코드 수 상위 9 + "More…" 목록.
- **(D34 개정) 미니 = 3D**: 카드 미니를 Sigma 2D 에서 본뷰와 동일한 3D 마크로
  교체하되, WebGL 컨텍스트는 **단일 렌더러의 setScissor/setViewport 분할**로
  1개만 사용(브라우저 컨텍스트 상한 ~16 회피). 정적 오블리크 컷(조용한 그리드),
  hover 동기화는 셀별 레이캐스트. 카드 헤더의 `↻` 칩 = 카드별 레이아웃
  프리셋(§1.7) 오버라이드.

### 3.2 Compare 뷰 — 두 도메인의 **개념 대 개념** 결합

"단순 도메인 단일 연결이 아닌 개념끼리의 연결"의 답. 진입: L0 에서 결합 엣지
클릭, 또는 Multiples 카드 2개 선택.

```
┌─ math (좌 렌즈) ──┐   ┌ 결합 레일 ┐   ┌─ physics (우 렌즈) ─┐
│  육각 노드들       │   │ cA ⇄ cB   │   │   육각 노드들        │
│  (자기 레이아웃)    │   │ cC ⇄ cD…  │   │   (자기 레이아웃)     │
└──────────────────┘   └──────────┘   └────────────────────┘
```

- 좌우 = 각 도메인의 L1 렌즈(자기 좌표). 중앙 **결합 레일** = 개념쌍 목록
  (`ListRow`): 결합 유형 표기(직접 엣지 = 파선 아이콘 / Bridge 매개 = 점선+마름모
  아이콘) + 매개 Bridge 명.
- 레일 hover = 양쪽 렌즈에서 해당 개념쌍 점등 + 사이에 임시 연결선(파선) 렌더.
  레일 클릭 = 양쪽 노드로 카메라 동시 맞춤.
- 정렬: 결합 강도(직접 엣지 수 + Bridge 매개 수) 내림차순.
- **데이터 계약(신설)**: `GET /coupling?a={dom}&b={dom}` →
  `{pairs:[{a_id, a_title, b_id, b_title, kind: direct|bridge, via?: bridge_id}]}`.
  직접 크로스도메인 엣지 ∪ Bridge CONNECTS 매개쌍. weg-9000 실데이터 실측:
  직접 엣지는 0(전부 도메인 내부), 결합은 Bridge 11개가 담당 — 매개쌍이 주 신호.
- 확장(후속 DEC): 임베딩 코사인 유사도 상위 k 쌍을 "제안된 결합"으로 레일 하단에
  점선 표기 — 검색 인덱스 재사용, 지능 반입 아님(결정론 kNN).

### 3.3 Coupling Matrix — 전 도메인 결합 히트맵

- L0 툴바 `Matrix` 토글: 도메인×도메인 그리드, 셀 = 결합 수(잉크 농도 3단 —
  모노크롬 시퀀셜). 셀 클릭 = 해당 쌍 Compare 뷰.
- 도메인 5개 이하일 땐 L0 지도가 이미 답이므로 Matrix 는 6+ 에서 기본 노출.

## 5. 공유(Share)의 UI 노출

원칙: **공유는 Packs 의 기능이 아니라 "스코프의 출구"다** — 사용자가 스코프를
보고 있는 모든 곳(렌즈·영역 선택·검색 오버레이)에서 한 동작으로 나간다.

### 5.1 내보내기 동선 3개 (전부 같은 시트로 수렴)

| 진입 | 스코프 |
|---|---|
| Atlas 영역 선택(§2 lasso) → `Share this slice` | 선택 노드 집합 |
| 노드 우클릭 → `Share slice from here` | seed+depth(기본 2, 시트에서 조절) |
| Packs 표면 `Share a slice` | domain/tags/seed 폼 |

**Share 시트(공통)** — 보내기 전에 무엇이 나가는지 전부 보여준다:
1. 스코프 요약: "{n} concepts · {k} connections · {m} records" + 포함 노드 목록
   (접힌 ListRow, 개별 제외 체크 가능 — 시트가 곧 최종 편집기)
2. 미포함 고지(신뢰 카피): *"Your pins, tags-as-signals and usage stay with you.
   The pack carries content only."*
3. 미리보기 미니 그래프(선택 영역만 렌더 — 받는 사람이 볼 모양)
4. CTA `Save pack file` → JSON 저장. 부 CTA `Copy summary`(매니페스트 텍스트)

### 5.2 들여오기 동선

드롭(앱 어디서든) 또는 Packs `Import a pack` →
**Import 미리보기 시트**: 매니페스트(작성일·스코프·counts) + 미니 그래프 +
겹침 예고("{x} of these already exist — they'll be updated in place") →
CTA `Import as mine` → 결과: "{created} new · {matched} updated" + `View in Atlas`.

### 5.3 수입 흔적(provenance) — DEC 후보 D23

- 수입 직후: Atlas 로 이동하면 새 노드들이 포인트색 초점 + `⇣` 표기로 1회 점등
