# GRAPH.md — 어시스턴트 쓰기 관례 계약

> 어시스턴트가 그래프에 **쓰기 전에** 읽는 마크다운 한 장. CLAUDE.md 가 코딩 관례에 대해
> 하는 일을 지식 구조화 관례에 대해 한다. 계획·근거는 `plans/PLAN-graph-md.md`,
> 연구 원본은 발주자 업로드 `GRAPH.MD 설계.md`.
>
> **채택(GM-1) 확정 2026-08-01.** 이 문서가 규격 정본이다.

## §1 왜 있는가

증상은 "같은 자료를 Claude 가 넣은 것과 Cursor 가 넣은 것의 모양이 다르다"이지만, 원인은
취향이 아니라 **채널 부재**다.

- MCP 도구 18종에 **어휘를 조회하는 도구가 없다** — 코드근거 `Vinc/vinc_mcp/tools.py:203`
  (`TOOLS` 전량). 재가된 타입 어휘 조회는 HTTP 전용이다(`Vinc/api/server.py:625` `read_types`).
- 그래서 어시스턴트는 어휘를 **쓰고 나서** `proposed_types` 로만 안다 —
  코드근거 `Vinc/api/fragment.py:484`.
- 재가·거부·개명은 MCP 에 노출하지 않는다. 이 비대칭은 의도된 것이고 유지한다
  (`Vinc/api/server.py:655`·`:664`·`:593`).

⇒ GRAPH.md 는 편의 문서가 아니라 **비어 있는 유일한 읽기 채널을 메우는 것**이다.
도구를 하나 더 다는 것(§6.2)보다 문서 한 장이 비용이 낮으므로 문서를 먼저 놓는다.

## §2 형태 규격

| # | 규칙 | 강제 |
|---|---|---|
| F1 | 한 파일·두 구역: 사람이 쓰는 산문 + 스토어가 쓰는 생성 블록. 경계는 주석 마커 | lint 3 |
| F2 | 60줄 초과 경고 · 100줄 초과 실패 | lint 8 |
| F3 | 가변성 태그 3분류(GM-11a, 2026-08-02 개정): ko `[스키마 고정]`/`[이 그래프가 정함]`/`[주제마다 다름]` · en `[schema-fixed]`/`[this graph decides]`/`[varies by topic]`. **파일 분리 금지** | 리뷰 |
| F4 | 명령형·2인칭. 독자는 어시스턴트다 | 리뷰 |
| F5 | 화면 노출 규칙 준수 — em-dash 금지(D38), 대체는 `·`·괄호·콜론 | lint 9 |

F3 근거(v0.1→v0.2 개정): 구 2분류 `[core]`(범용)/`[vinc]`(바인딩)는 **출처** 축이라 독자가
알아야 할 **가변성**과 뒤집혀 읽혔다 — 스키마가 강제하는 노드 5종·관계 6종에 `[vinc]` 가
붙어 "Vinc 것이니 내가 정하면 된다"로 오독됐다(GM-11a 판정 근거, 실측). 신 3분류는 "이
파일로 바꿀 수 있는가"를 직접 답한다: 스키마 고정(불가) · 이 그래프가 정함(이 그래프의
관례) · 주제마다 다름(주제에 맞춰 고쳐 써라). 검증기(`HEADING_RE`)는 기존 사용자 파일을
위해 **신·구 어휘를 모두 받되** 템플릿은 신 태그만 낸다. 구 근거였던 "코어 추출 보류"
(구현체 1개, DESIGN.md 선례)는 파일 분리 금지 조항으로 존속한다.

F5 근거: 이 템플릿은 문서 사이트 코드블록으로 그대로 실린다. 내부 문서 규칙이 아니라
**제품 카피 규칙**을 따른다.

## §3 절 구성

| 절 | 구역 | 담는 것 | 없으면 망가지는 것 | 기계검증 |
|---|---|---|---|---|
| 헤더 | 생성 | 규격 버전·생성 시각·정본 선언 | 드리프트 감지 기준점 소실 | 예 |
| What this is | 사람 | 이 파일의 지위·의미 판단 주체 | 어시스턴트가 이 파일을 스펙으로 오인 | 아니오 |
| Read before you write | 사람 | 검색 먼저·id 재사용·id 접두 규약 | 중복 개념 양산 | 부분 |
| Node kinds | 사람 | 5종 정의 + 개방형 타입의 운명 | 같은 자료가 호스트마다 다른 라벨 | 부분 |
| Granularity | 사람 | 양 2 · 음 3 예시 + 2문장 테스트 | 개념 비대·파편화 | 아니오 |
| Relations | 사람 | wire 6종·방향의 의미·relates_to 무방향 | 방향 역전으로 선행 그래프 붕괴 | 예 |
| Documents | 사람 | `vinc_doc_put` 경로 고정, Record 복붙 금지 | D54 형 "출처 없음" 재발 | 예 |
| Domains in this graph | 생성 | 실 도메인 목록 + 표기 규칙 | 도메인 분열 | 예 |
| Ratified vocabulary | 생성 | 재가된 node/edge 타입 | 제안만 쌓임 | 예 |
| Do not | 사람 | 금지 3줄(자기재가 금지 포함) | 재가 비대칭 훼손 | 부분 |

절은 10개, 그중 **사람이 손대는 것은 7절 약 35줄**이다.

입도를 규칙이 아니라 예시로 적는 근거: Zettelkasten 이 "one idea per note" 를 정밀화하다
결국 각자의 판단으로 후퇴한 60년 이력(출처확인, 연구 보고서 Key Findings 5).
규칙으로 적으면 지켜지지 않고, 예시는 지켜진다.

## §4 템플릿

**EN 이 정본**이고 ko 는 1:1 이식이다. 생성 구역의 값은 언어와 무관하게 같은 소스에서 나온다.

**텍스트 정본은 코드다** — `Vinc/api/graphmd.py` 의 `_TPL_EN`·`_TPL_KO` 상수(as-built 2026-08-01).
문서 사이트 `/docs/mcp/graph-md/` 의 코드블록은 그 사본이므로 **함께 고쳐야 한다.**
(대조 실측 2026-08-01: 58줄 중 다른 줄은 2줄뿐이고 둘 다 생성 구역의 예시 값이다 — 페이지는
채워진 예를 보이고 코드는 빈 그래프를 낸다. 산문은 전부 일치.)

| 절 (EN) | 절 (ko) | 줄수 |
|---|---|---|
| What this is | 이 파일은 무엇인가 | 3 |
| Read before you write | 쓰기 전에 읽을 것 | 4 |
| Node kinds | 노드 종류 | 8 |
| How big is one concept | 개념 하나의 크기 | 9 |
| Relations | 관계 | 8 |
| Documents | 문서 | 4 |
| (생성) Domains in this graph | 이 그래프의 도메인 | 3 |
| (생성) Ratified vocabulary | 재가된 어휘 | 4 |
| Do not | 하지 말 것 | 4 |

**실측 60줄**(공백 포함, 2026-08-02 GM-11a 로 입도 절 +2줄: 개체·개념 구분 — "두 문장
기준은 인물·제품에도 통과하니 재사용 관념인지 함께 묻고, 세상의 개체는 Entity·record 로").
60줄 예산의 **여유는 0줄이다** — lint 8 경고선(`n > 60`)에 정확히 닿기 직전이며, EN/ko
동일 줄수는 테스트(`test_templates_are_line_for_line_parallel`)가 고정한다.

⇒ 예산이 꽉 찼다. **한 줄을 더하려면 한 줄을 지워야 한다.** 아래 §4 말미의
`content_time` 줄을 넣으려면 기존 산문 한 줄을 빼야 한다(61줄 = lint 8 FIX). 그때는 예시 하나를 뺀다.

⚠ `content_time`(D72) 을 지시하는 줄은 **템플릿에 없다**. MCP `vinc_doc_put` 이 그 필드를
전달하지 않기 때문이다(§6.4). 읽기는 되므로(`vinc_doc_list` 가 돌려준다) "읽어서 시간 맥락으로
쓰라"는 줄은 유효하지만, 60줄 예산과 GM-6 결과를 함께 보고 넣는다.

## §5 생성 구역 명세

| 생성 줄 | 소스 | 코드근거 |
|---|---|---|
| 헤더 `built` | 생성 시각(규격 버전은 상수) | 생성기 |
| 도메인 목록 | `q.domains(owner)` → `{domain, episodes, concepts, records, total}` | `Vinc/api/query.py:280` |
| 재가 node/edge 타입 | `themes.list_types(theme_id, status="authored")` | `Vinc/store/theme_store.py:193` |

⚠ 상태 문자열은 **`authored`** 다("ratified" 가 아니다) — 재가는 `proposed → authored` 전이다
(`Vinc/store/theme_store.py:213` `ratify`). 이 이름을 틀리면 재가 어휘가 늘 빈 목록으로 나온다.

- 상위 12개 + 나머지는 "외 N개". 목록이 길어지면 60줄 예산을 먹는다.
- **생성기는 사이드카·앱에서 돈다.** 어휘 조회가 HTTP 전용이라 어시스턴트가 만들 수 없고,
  만들게 해서도 안 된다(재가 비대칭).
- **경계**: 생성기는 위 3종만 쓴다. 노드 정의문·입도 예시·금지 목록은 생성하지 않는다.
  자동 생성 컨텍스트 파일이 태스크 성공률을 떨어뜨린다는 외부 연구(출처확인 arXiv:2602.11988,
  코딩 에이전트 대상이라 그래프 적재로의 외삽은 `추정`)를 이 경계로 흡수한다.
- **빈 그래프**: 도메인 0개면 목록 대신 한 줄을 쓴다. "아직 도메인이 없습니다. 첫 적재가
  도메인을 만듭니다." 빈 목록을 그대로 두면 어시스턴트가 "도메인 금지"로 오독한다(`판단`).

## §6 배치

### 6.1 4안 판정

| 안 | 코드 비용 | 사람 개입 | 계정 그래프 추종 | 판정 |
|---|---|---|---|---|
| (a) 사용자 리포 파일 | 0 | "읽어라" 필요 | 안 됨 | Phase 1 |
| (b) 스토어 문서 `graph.md` | 소 | "가져와라" 필요 | 됨 | Phase 2 |
| (c) MCP resource | 중 | 호스트마다 다름 | 됨 | **보류** |
| (d) 읽기 도구 `vinc_conventions` | 소 | **불필요** | 됨 | Phase 3 |

(c) 보류 근거 셋(각각 독립적으로 성립): ① 서버가 resources 를 선언하지 않는다 —
`capabilities: {"tools": {}}` 코드근거 `Vinc/vinc_mcp/rpc.py:114` ② resources 는 애플리케이션
제어라 모델이 스스로 못 부른다(출처확인 MCP 스펙) ③ `initialize` 응답 표면 확장은 실사고
이력이 있다(2026-07-31 claude.ai 커넥터 연결 실패 — 동 파일 주석).

### 6.2 (d) 설계 — as-built 2026-08-01

```
vinc_conventions  (읽기 전용, readOnlyHint · 도구 19번째)
  in : {owner?, lang?, target?}
  out: {text, source: "doc" | "default", doc_id, updated_at?, missing?: true}
```

구현: `Vinc/api/server.py` `read_conventions` + 라우트 `/conventions` ·
`Vinc/vinc_mcp/tools.py` `_t_conventions`. 웹 패리티를 위해 허브 `_PROXY_OPS` 와
계정 `GET_OPS` **양쪽에 함께 등재**했다(둘이 어긋나면 그 화면만 조용히 404 로 죽는다 —
합계 뷰 실사고 계열).

스토어에 `graph.md` 가 있으면 그 본문을, 없으면 **생성 구역만 채운 기본 템플릿**을 돌려준다.
사용자가 아무것도 안 해도 도메인·재가 어휘는 전달된다.

`vinc_ingest` 설명문 끝에 한 문장을 더한다:
`Call vinc_conventions once before your first write in a session.`
도구 설명은 모델 제어이고 `tools/list` 로 항상 실린다(`Vinc/vinc_mcp/rpc.py:119`).
**이 한 문장이 "아무도 안 읽는다" 실패 모드에 대한 유일한 구조적 방어다.**

### 6.3 (b) 를 켜기 전 처리할 지뢰 2개

| 지뢰 | 코드근거 | 처리 |
|---|---|---|
| 로컬↔계정 동기화가 서로의 관례 문서를 덮어씀 | `Vinc/api/docsync.py:32` (owner 문서 전량 열거, 제외 없음) | `export_docs` 에서 `doc_id='graph.md'` 제외. **각 그래프는 자기 관례를 갖는다**가 불변식 |
| 관례 문서 조각이 검색·파생에 섞임 | `Vinc/api/docstore.py:265` 이후 청킹 | `origin="vinc:conventions"` 표식 먼저, 검색 제외는 실측 후(GM-7) |

고정 id 배치가 가능한 근거: `doc_id = doc_id or make_doc_id(...)`
(`Vinc/api/docstore.py:252`) 뒤 `MERGE (d:_DocMeta {doc_id: $id})`(`:312`).

### 6.4 `content_time` 비대칭 (GM-6)

- HTTP `/doc/put` 은 받는다 — `Vinc/api/server.py:488`.
- MCP `vinc_doc_put` 은 **전달하지 않는다** — `Vinc/vinc_mcp/tools.py:190`.
- `vinc_doc_list` 는 **돌려준다** — `Vinc/api/docstore.py:529` + `Vinc/api/server.py:474`.

⇒ 비대칭은 "모른다"가 아니라 **"읽을 수 있는데 쓸 수만 없다"**. 노출 여부는 판단이 아니라
실측으로 가른다(프로토콜은 `plans/PLAN-graph-md.md` §8.1). GM-1 의 블로커가 아니다.

## §7 정본 규칙 (GM-3)

**구역별로 정본이 다르다.**

| 구역 | 정본 | 편집 주체 | 어긋나면 |
|---|---|---|---|
| 생성(도메인·재가 어휘) | 스토어 | 생성기 전용 | lint 4 `generated-drift` 실패 → 재생성 |
| 산문(정의·입도·금지) | 이 파일 | 사람 | 스토어에 대응물이 없다(비교 불가) |

한 문장 규정: **"스토어가 아는 것은 스토어가 쓴다. 스토어가 모르는 것만 사람이 쓴다."**

## §8 검증 (GM-4)

형상·참조 무결성만. **의미 검증은 넣지 않는다**(원칙 위반).

|---|---|---|
| 1 | `header-marker` 첫 줄 마커·규격 버전 파싱 | BLOCK |
| 2 | `section-order` 필수 절 존재·순서 | BLOCK |
| 3 | `generated-block` 마커 쌍·순서 | BLOCK |
| 4 | `generated-drift` 생성 구역 ≠ 현재 스토어 census | BLOCK |
| 5 | `unknown-edge` 관계 절 이름이 wire 6종 + 재가 어휘 밖 | BLOCK |
| 6 | `unknown-domain` 도메인 절 항목이 실 데이터에 없음 | FIX |
| 7 | `stale-tool` 본문의 `vinc_*` 가 `TOOLS` 에 없음 | FIX |
| 8 | `length` 60줄 초과 FIX / 100줄 초과 | BLOCK |
| 9 | `forbidden-glyph` em-dash 등 화면 금지 문자(D38) | FIX |

**as-built 2026-08-01** — 구현 `Vinc/api/graphmd.py`, CLI `Vinc/api/cli.py`, 테스트
`Vinc/tests/test_graphmd.py`(18건).

```
vinc graph-md build --owner O [--out FILE | --file FILE | --doc] [--lang en|ko]
vinc graph-md check --owner O [--file FILE | --doc] [--no-store]
```

- `--file` 은 **제자리 갱신**이다: 생성 구역만 갈아 끼우고 헤더 날짜를 다시 찍는다.
  **산문은 건드리지 않는다** — build 가 사람이 쓴 예시를 지우면 아무도 이 명령을 두 번 쓰지 않는다.
- 마커가 깨진 파일은 **교체하지 않고 오류로 돌린다**(어디였는지 추측하지 않는다).
- `--doc` 은 스토어의 `graph.md`(§6.3)를 읽고 쓴다. 이때만 `origin="vinc:conventions"` 을 단다.
- `--no-store` 는 형상 규칙만 돌린다(스토어 없이 CI 에서 쓸 수 있다). `--doc` 과 함께 오면
  `--doc` 이 이긴다(읽을 곳 자체가 스토어다).
- exit code 는 기존 게이트와 동형: `0` PASS · `1` FIX-only · `2` BLOCK
  (선례 `Vinc-docs/CONVENTIONS.md §3`). 실측 확인 2026-08-01.
- 규칙 4·5·6·7 은 스토어를 읽으므로 검증기는 사이드카 옆에서 돈다.

**언어 판별**: 절 제목으로 EN·ko 를 가른다. 둘 다 아니면 9건을 BLOCK 으로 쏟지 않고
`section-order` FIX 하나로 강등한다 — 우리가 두 언어만 출하하는 것이지, 사용자가 제 언어로
번역한 파일이 틀린 것은 아니다.

## §9 Atlas·앱에서의 노출과 관리

### 9.1 전제 — 저장은 문서지만, 문서로 **보이면 안 된다**

`graph.md` 를 그냥 문서로 두면 네 가지가 동시에 일어난다. 넷 다 코드근거가 있다.

| 일어나는 일 | 코드근거 | 왜 나쁜가 |
|---|---|---|
| "모든 문서" 목록에 섞이고, 개념 링크가 없어 **"주제 없음"** 묶음에 앉는다 | `Vinc/app/src/surfaces/records.ts` (주제는 `MENTIONS→Concept.domain` 유도, 없으면 주제 없음) | 사용자의 실제 자료 사이에 관리 파일이 낀다 |
| 문서 편집기가 **개념 추출 후보를 자동 제시**한다 | `Vinc/app/src/doc-editor.ts:285` | `## Node kinds` 같은 헤딩이 개념 후보로 뜬다 |
| 사용자가 [반영]을 누르면 그 헤딩이 **Concept 으로 MERGE** 된다 | `Vinc/api/docstore.py:817` `extract_concepts`(마크다운 헤딩 → 후보) · `:907` (`status='proposed'`) | **관례 문서가 Atlas 를 오염시킨다.** 가장 큰 위험 |
| 동기화로 로컬↔계정 관례가 서로 덮어쓴다 | `Vinc/api/docsync.py:32` | 계정 그래프가 로컬 도메인 목록을 주장한다 |

세 번째가 결정적이다. 개념 추출은 **자동이 아니라 사용자 클릭**이므로(`apply=True` 경로만
MERGE — `docstore.extract_doc`) 오늘 당장 터지지는 않는다. 그러나 **UI 가 그 클릭을 권한다.**
관례 문서에 대해서는 추출 상자를 띄우지 않는 것이 맞다.

### 9.2 판정 — Atlas 에 노드로 그리지 않는다

이유 셋:

1. **5종 라벨 중 어느 것도 아니다.** Concept 도 Episode 도 아니고, 억지로 넣으면 그 자체가
   관례 위반의 실례가 된다.
2. **고아 점이 된다.** Atlas L0 는 개념·주제 축으로 배치한다. 연결이 없는 점은 "아직 제자리를
   못 찾은 개념"이라는 기존 신호를 갖는데(문서 사이트 `/docs/use-cases/` 카피), 관례 파일이
   그 신호를 거짓으로 켠다.
3. **관례가 데이터인 척한다.** 이 파일은 그래프에 **대한** 것이지 그래프의 일부가 아니다.
   지도 위에 범례를 그려 넣는 것과 같다.

### 9.3 자리 — 상단 바 아이콘 1개 + 통제 시트 (발주자 결정 2026-08-01)

**아이콘 하나가 두 일을 겸한다.** 상단 바에 아이콘 전용 버튼을 하나 더하고, 누르면 열리는
시트에 두 구역을 담는다.

| 구역 | 내용 |
|---|---|
| 위 · 관례 | GRAPH.md 문서 편집기. 생성 구역(마커 사이)은 **읽기 전용**으로 칠한다 |
| 아래 · 재가 대기 | 제안된 타입·도메인 목록. 승인·거부·개명(라우트는 이미 있다 — §9.4) |

아이콘에 **뱃지 N**(제안 적체 수)을 얹는다.

초안은 Settings › Connections 탭을 권했으나 **뒤집는다.** 빈도만 보면 Settings 가 맞다(셋업 때
한 번 + 가끔). 그러나 안 보이면 만들지 않고, 만들지 않으면 이 기능은 첫 번째 실패 모드
("아무도 안 쓴다")로 죽는다. **발견성이 빈도를 이긴다.**

⚠ **조건부 결정이다.** 상단 바에는 "보이는 손잡이는 반드시 무언가를 한다"는 규율이 있고
(`Vinc/app/src/topbar.ts:13`), 현재 7개(로고·렌즈·관점·검색·가져오기·공유·설정)로 이미 빡빡하다.
**뱃지가 없으면 이 아이콘은 상단 바에 있을 자격이 없다** — 한 달에 한 번 누르는 버튼이 픽셀을
상시 점유할 근거가 없기 때문이다. 즉 **GM-8 을 함께 승인해야 이 배치가 성립한다.**
GM-8 을 안 하면 Settings › Connections 로 되돌린다.

한 화면에 붙이는 이유: 사전 예방(관례)과 사후 교정(재가)을 다른 화면에 두면, 사용자는
"관례를 적었는데 왜 여전히 제안이 쌓이지"를 서로 다른 자리에서 겪는다.

4-State 선언(D 계층 공통 규약 `vinc.d.index` 준수):

| 상태 | 화면 |
|---|---|
| Empty | "아직 관례가 없습니다" + 생성 미리보기(도메인·재가 어휘는 이미 채워진 상태로 보여 준다) + [관례 만들기] |
| Loading | 생성/대조 중 |
| Success | 마지막 생성 시각 · 드리프트 없음 표시 · [편집] [다시 생성] |
| Error | 스토어 대조 실패 사유(사이드카 미기동 등) + 재시도 |

편집기 규율: **생성 구역은 읽기 전용**으로 칠한다(마커 사이). 손으로 고치면 다음 재생성에
지워지므로, 고칠 수 있게 두는 것 자체가 거짓말이다.

**as-built 2026-08-01** — `Vinc/app/src/conventions.ts` · 상단 바 `#tb-conv`(아이콘 `check`) ·
`POST /conventions/build`. 편집기는 textarea 하나가 아니라 **앞산문·생성구역(`<pre>`)·뒷산문**
셋으로 쪼갰다(읽기 전용을 CSS 로 흉내 내지 않고 구조로 강제). [다시 생성]은 **저장을 먼저**
한다 — 안 그러면 서버가 읽는 것이 옛 산문이라 방금 쓴 문장이 한 번에 사라진 것처럼 보인다.

⚠ **뱃지는 `provenance:ingest_proposed` 만 센다.** 주제를 만들면 내장 어휘가
`status:proposed, provenance:system_draft` 로 함께 깔려(`store/theme_store.py:14`),
전부 세면 **첫 실행부터 뱃지가 11** 이 된다(실측). 사용자가 제안한 적 없는 8개를 판정하라고
요구하는 순간 뱃지는 신호이기를 그만둔다. 재가를 기다리는 것은 어시스턴트가 실제로 제안한
것뿐이다.

⚠ **재가 구역은 셸 전용이다.** 주제 어휘에는 owner 차원이 없어 계정 프록시가 `themes`/`types`
를 의도적으로 막는다(`vinc_mcp/http_server.py` `_PROXY_OPS` 주석). 웹에서는 관례 구역만 보이고
승인은 데스크톱에서 한다고 말한다.

⚠ **vite dev 프록시(`app/vite.config.ts` `API_RE`)에도 등재해야 한다.** 빠지면 그 요청만
`index.html`(200)을 받아 앱이 "사이드카가 꺼졌다"고 오진한다(선례: 12종 누락으로 Sankey·Reader
사망). 즉 새 라우트의 등재처는 **네 곳**이다: 사이드카 라우트 표 · 허브 `_PROXY_OPS` ·
계정 `GET_OPS` · vite `API_RE`.

### 9.4 Atlas 가 보여야 할 것 — 관례가 아니라 **제안 적체**

Atlas 에 실려야 하는 것은 GRAPH.md 자체가 아니라 **그것이 줄이려는 것**이다.

여기서 실측 하나가 나왔다. **재가 UI 가 앱에 없다.** 라우트는 사이드카에 있는데
(`Vinc/api/server.py:1021` `/types` · `:1063` `/types/ratify`·`/types/reject`), 앱 소스에서
이 경로를 부르는 곳이 0이다(`Vinc/app/src` 전량 검색 — `ratify` 0건).

⇒ "어시스턴트는 제안하고 **사람이 재가한다**"는 원칙은 지금 **사람이 재가할 자리가 없는
약속**이다. 제안은 쌓이기만 한다.

그래서 GRAPH.md 와 재가 화면은 한 쌍이다. 전자는 사전 예방, 후자는 사후 교정이고 **지금 둘 다
없다.** Atlas 쪽 권고는 다음 하나로 좁힌다:

- 표식은 **§9.3 의 상단 바 아이콘 뱃지**로 낸다(Atlas 툴바가 아니다 — Atlas 를 떠나도 유효한
  상태이므로 셸 크롬에 붙는 것이 맞다). 누르면 통제 시트의 아래 구역이 열린다.
  라우트는 이미 있으므로 **UI 만** 만들면 된다.
- 이 표식은 GRAPH.md 의 효과 측정치(§`PLAN-graph-md.md` §8 지표 P)를 사용자에게도 그대로
  보여 준다. 지표와 화면이 같은 수를 가리키는 편이 낫다.

이것은 GM-1 의 범위 밖이라 **새 결정 GM-8 로 분리**한다(§10).

### 9.5 팩·공유에서의 취급

관례 문서는 `.vincpack` 에 **싣지 않는다**(기본값). 근거는 §6.3 동기화 지뢰와 같은 계열이다.
남의 관례가 내 그래프의 도메인 목록을 주장하면, 받은 쪽에서 그 문서는 즉시 거짓이 된다.
팩으로 관례를 나누고 싶다는 요구가 실제로 관측되면 그때 "참고용 첨부(적용 안 함)"로 다시 연다.

### 9.6 화면 카피 규칙

- em-dash 금지(D38). 템플릿 코드블록 안까지 포함.
- **용어가 표면마다 다르다(관측)**: 앱 카피는 "그래프"(`Vinc/app/src/copy.ts` 8건, "온톨로지"
  0건), 문서 사이트는 "온톨로지". 각 표면의 현행 용어를 따르고 섞지 않는다. 통일은 별건이다.
- 이 기능의 이름은 화면에서 "관례"로 고정한다. "규칙"은 강제력을 암시해 §9.2-3 과 어긋나고,
  "설정"은 이미 다른 뜻으로 쓰인다.
