# Atlas 3D/2D 가시성 재설계 연구

> **지위: 연구 입력(research-input).** 채택은 발주자 결정(DEC)으로만 정본화된다.
> 발주자 관찰(2026-08-02): "축소 시 완전히 어두워진다. 배경·노드·호버·글자 색이
> 잘 안 보인다. 노드 구별 자체가 안 된다. 디자인을 완전히 바꿔서라도 시각적으로
> 잘 보이게 하되, 과하지 않게." 본 문서는 그 관찰의 **코드 수준 원인 진단**(전부
> 실측·계산 근거), **외부 조사**, 그리고 **구체 수치를 단 재설계 제안**이다.
> 진단의 코드 앵커는 2026-08-02 HEAD 기준이다.

## §1 원인 상세

### 1.1 C1 — fog 가 "깊이 단서"가 아니라 "소멸 장치"로 동작한다

`scene.fog = new THREE.Fog(pal.fog, S*2.6, S*9)` (atlas3d.ts:324). fog 색 = 배경색,
S = 140×spread. 초기 카메라는 `(S·1.1, S·0.9, S·2.1)` → 원점 거리 ≈ S·2.53 으로
**기본 프레이밍에서 이미 fog 시작 구간**이다. 사용자가 휠로 축소하면 카메라 거리가
S·5~9 로 늘고, 전 노드가 fog near→far 구간에 들어가 배경색으로 선형 소멸한다.
다크는 흑화, 라이트는 백화 — 발주자 관찰 그대로다. three.js 의 Fog 는 카메라
거리 기반 고정 파라미터라, **줌과 무관하게 "장면의 크기"에만 맞춘 현행 상수는
축소를 페널티로 만든다**(외부 조사 §2.5 — fog 는 연출 장치이지 가독성 장치가 아니며,
가독성 목적이면 카메라 적응이 필요하다).

### 1.2 C2 — 성좌 티어의 위계가 "보임/안 보임"으로 붕괴했다

다크 글로우 모드(atlas3d.ts:183-204)의 의도는 "초점은 빛나고 주변은 잦아드는 성단"
이다. 문제는 잦아듦의 바닥이 없다는 것: far fill `#191C2A` 는 **카드 배경색과 동일
토큰**이라 배경 위에서 1.15:1 — 후퇴가 아니라 소멸이다. 티어 배정(atlas3d.ts:113-117,
무초점 시 degree 프록시: ≥8 near · ≥2 mid · 나머지 far)상 실그래프의 다수가 far 로
떨어지므로, L0 첫 화면부터 "노드 대부분이 안 보이는" 상태가 기본값이 된다.
mid/far 의 stroke 링(`#6E7189`, 4.05:1)이 유일한 합격 채널인데 두께가 r×0.12
(하한 0.4 월드 단위)라 축소 시 서브픽셀로 사라진다.

### 1.3 C3 — 엣지의 "농도 사다리"가 다크에서 배경 밑으로 내려갔다

D33 의 결정(굵기 아닌 농도=서열)은 유지할 가치가 있으나, 다크 사다리의 **모든
계단이 3:1 아래**에 놓였다: 2D 는 `mix(#262A3D → 배경)` 으로 시작점부터 1.37:1 인
선을 더 배경 쪽으로 섞고(1.20~1.26:1), 3D 는 cross 가 `#3A4070`(1.98:1)이다.
사다리의 **꼭대기**(방향 엣지 inkMute `#6E7189` = 4.05:1)만 보인다 — "선이 안
보인다"는 관찰과 일치한다.

### 1.4 C4 — hover 후퇴가 정본의 3.75배 강하다 (규정 위반)

정본(D32-a, [[vinc.d.atlas-visual-language]] §1.6)은 물러남을 **토큰으로만** 참조하고
값은 노드 0.40 · 선 0.12 · 텍스트 0.35 로 못박았다. 2D 는 CSS `--recede-*` 를 읽어
준수하는데(atlas2d.ts:52-58), **3D hover 는 `base × 0.15` 숫자 리터럴**이다
(atlas3d.ts:399-425). 0.72×0.15 = 실효 불투명도 0.108 → 비이웃이 1.05~1.15:1 로
소멸한다. "hover 시 색이 잘 안 보인다"의 직접 원인이며, 수리는 재설계가 아니라
**정본 준수 회복**이다.

### 1.5 C5 — 형태 채널이 3D 다크에서 반쯤, 2D 에서 완전히 꺼져 있다

- 3D 다크 글로우: `MeshBasicMaterial`(무조명)이라 음영이 없어, 구와 정팔면체와
  육각기둥이 **실루엣 외곽선만**으로 구별돼야 하는데 축소 시 수 픽셀이 된다.
  D35 의 "형태=타입"이 정확히 필요한 순간(멀리서 조망)에 작동을 멈춘다.
- 2D: sigma 노드 프로그램 미등록 — 전부 원. 범례(atlas.ts:194-197)는 원·육각·
  마름모·링구 4형태를 가르치므로 **화면이 범례를 반박**한다(코드 자신이 선 문법에
  적용한 "그리지 않는 문법을 가르치지 말라" 규율의 형태판 위반).
- 라벨: 3D 는 허브 상위 8 + hover 뿐이고 스프라이트가 월드 스케일이라 축소 시
  픽셀화된다(Obsidian 커뮤니티에 동일 불만 다수 — §2.4). 2D 는 8px 문턱이라
  균일 크기 모드에서 상시 라벨이 0 이 된다.

## §2 외부 조사

### 2.1 WCAG 1.4.11 — 비텍스트 대비 (수용 기준으로 채택 권고)

그래픽 객체(차트 마크·아이콘·포커스 표시)는 인접 배경 대비 **최소 3:1**. 포커스
표시도 동일. 다크 모드는 라이트에서 통과한 값도 **전부 재계산**해야 하며 전용
팔레트가 필요하다. Vinc 는 텍스트(15.8:1)는 우수하나 **마크가 체계적으로 미달**이다.
→ 본 문서의 모든 제안은 "마크·포커스·선 최소 3:1(의도적 후퇴 채널 제외), 후퇴
채널에도 하한 명시"를 수용 기준으로 삼는다.

### 2.2 다크 모드 데이터 시각화 관례

순수 검정 배경 회피(#121212 급 권장 — Vinc `#0C0D13` 은 관례 부합), 순백 회피
(#F0F0F0 급 — Vinc `#E8E7EF` 부합), **1차 정보 = 최고 대비 / 2차 정보 = 중간 회색**
의 2단 위계, 색상환 대신 패턴·직접 라벨 병용. Vinc 의 문제는 관례 위반이 아니라
**"2차 정보" 계층을 3:1 아래로 눌러버린 것** — 위계는 3:1 위에서도 만들 수 있다
(예: 4:1 vs 7:1 vs 10:1 사다리).

### 2.3 지각 연구 — 형태는 "아마도 preattentive", 크기·명도가 강하다

Bertin 망막 변수 계열 연구: 크기(size)·명도(value)는 확실한 preattentive 채널,
**형태(shape)는 "probably preattentive"** 로 한 단계 약하다. 함의 둘:
① 축소 시 수 픽셀이 되는 마크에서 형태 단독 변별은 원리적으로 무리 — **형태는
근거리 채널, 원거리는 크기·명도(+글로우)로 이관**하는 LOD 가 지각적으로 옳다.
② 형태 종류는 3~4종 이하로 유지(현행 4종은 적정) — 늘리는 방향은 금물.

### 2.4 도구 선례

- **Obsidian 그래프 뷰**: "줌아웃 시 텍스트가 픽셀화되어 못 읽는다", "텍스트 페이드
  문턱이 노드 크기를 고려해야 한다"는 불만·요청이 다년간 반복 — 라벨을 월드
  스케일 스프라이트로 두면 생기는 전형적 실패. 플러그인 생태계(Beautiful Graph 의
  label threshold, Advanced Graph 의 N-hop 포커스 페이드)가 수요를 증명한다.
- **sigma.js**: 노드·엣지 크기를 `√(zoom ratio)` 로 스케일해 줌 전 구간에서
  "적당한 화면 크기"를 유지(`zoomToSizeRatioFunction`). **줌 적응 크기라는 해법이
  이미 2D 렌더러에 내장**돼 있고, 3D 쪽에만 없다.
- **three.js fog**: 문헌 공통 — fog 는 분위기·깊이 연출 장치. 가독성 유지가 목표면
  카메라 거리에 fog 파라미터를 연동하거나 셰이더 기반 높이/지수 fog 로 대체한다.

### 2.5 요약 — 외부 조사가 지지하는 방향

"완전히 바꿔야 할 것"은 마크의 형태가 아니라 **①대비 바닥(3:1 하한) ②줌 적응
(fog·크기·라벨) ③채널 역할 분담(근거리=형태·질감, 원거리=크기·명도)** 세 축이다.
모노크롬+초점 1색 규율(D20·D39)은 외부 관례와도 충돌하지 않는다 — 붕괴한 것은
규율이 아니라 **사다리의 눈금**이다.

## §3 재설계 제안 (R1~R8, 구체 수치)

닫힌 층(형태=타입, 초점색 1점, 모노크롬)은 유지한다. 바꾸는 것은 눈금·적응·준수다.
"과하지 않게"의 조작적 정의: **잉크 총량을 늘리지 않고**(글로우·색 추가 금지),
있던 채널의 하한과 스케일만 고친다.

| # | 제안 | 구체 수치 | 성격 |
|---|---|---|---|
| **R1** | **fog 카메라 적응** — 매 프레임(또는 controls change 이벤트) `fog.near = dist×1.5, fog.far = dist×4.5` (dist = 카메라~장면중심 거리). 축소해도 "보이는 것의 비율"이 불변이 된다. 대안: fog 전면 제거 + 티어 명도만으로 깊이 표현(성능 동일) | near 1.5d · far 4.5d | 버그 수리에 준함 |
| **R2** | **티어 fill 하한 재보정** — far `#191C2A`→**`#5E6484`**(3.35:1) 또는 stroke 승격안: fill 은 두되 stroke `#6E7189` 를 **상시 외곽선**(스크린 스페이스 최소 1.5px)으로. 권고는 후자 — 성단의 "깊이" 인상을 지키면서 경계 대비로 1.4.11 을 만족(경계 대비도 합격 기준) | far stroke ≥4:1 · 최소 1.5px | DEC(팔레트는 닫힌 층) |
| **R3** | **엣지 사다리를 3:1 위로 재배치** — 다크: 방향(뼈대) `#8F96D9`(6.96) · 무방향 `#6E7189`(4.05) · 크로스 `#565C7A`(2.96≈3, 파선 병행 시 허용) · 후퇴(fade) 만 3:1 미만 허용하되 **1.4:1 하한 명문화**. 2D 의 `mix(선, 배경, t)` 는 **mixFloor(fg, bg, 최소대비)** 함수로 교체 — 섞다가 3:1 을 깨면 거기서 멈춘다. 라이트 동형(fade `#DEDEDA` 1.20:1 도 동일 하한 적용) | 표 참조 | DEC(D33 개정) |
| **R4** | **hover 후퇴 정본 준수** — atlas3d 의 `×0.15` 리터럴을 `recede.node = 0.40` 토큰 참조로 정정(선 0.12·텍스트 0.35 동반). 실효 대비 near 기준 1.15→≈2.8:1 | 0.40/0.12/0.35 | **정본 위반 수리**(DEC 불요) |
| **R5** | **라벨 스크린 스페이스화 + 헤일로** — ① 3D 라벨 스프라이트를 카메라 거리 비례로 역보정(스크린 고정 크기, sigma 의 √zoom 관례 이식) ② 캔버스 베이크 시 `strokeText` 2px 외곽선(배경색) = 헤일로 — 어떤 마크 위에서도 판독 ③ 상시 라벨 수를 고정 8 이 아니라 **화면 밀도 기반**(뷰포트당 라벨 픽셀 점유 상한)으로 | halo 2px · 밀도 상한 | 열린 층 확장 |
| **R6** | **줌 LOD 2단** — 근거리(형태 판독 가능 구간): 현행 유리+형태. 원거리(마크 < 6px 화면 크기): 형태 렌더를 **점+크기+명도**로 강등하고(§2.3 지각 근거) 클러스터(도메인 가지) 라벨을 대신 띄운다. D74 폭발 배치가 가지 구조를 이미 좌표에 실었으므로 가지 중심 라벨은 좌표 평균으로 결정론 산출 가능 | 전환 문턱 6px | DEC(신규) |
| **R7** | **3D 다크 노드 최소 음영 복원** — 글로우 모드의 MeshBasic 을 유지하되 mid/far 에 한해 상단 45° 그라데이션 텍스처(1회 베이크) 또는 MeshLambert 저강도 조명으로 실루엣 내부에 명암 1단 — 형태 변별이 근거리에서 살아난다. 잉크 총량 불변 | 명암 1단 | DEC(D39/D40 보강) |
| **R8** | **2D 형태 3종 도입** — sigma 커스텀 노드 프로그램으로 원(개념)·사각(기록물)·마름모(다리) 3종만(§2.3 — 4종 초과 금지, 링구는 2D 에서 도메인 노드가 없으므로 불요). 범례-화면 자기반박 해소. 프로그램 3개 × 각 ~40줄 수준(sigma 공식 예제 존재) | 3종 | DEC(D46 보강) |

**우선순위 권고**: R4(위반 수리) → R1(축소 흑화의 주범) → R3(선) → R2(노드) →
R5(라벨) → R7 → R8 → R6. R1+R4 만으로 "축소 시 소멸"과 "hover 시 소멸"이 사라지고,
R2+R3 로 3:1 바닥이 선다. R5~R8 은 변별력 향상분이다.

## §4 검증 계획 (게이트)

1. **대비 계약 테스트** — `Vinc-design` 토큰 생성기(gen_theme_ts)에 assert 추가:
   `atlasScene.node.*.fill|stroke` 와 `linkRamp.*`(fade 제외) 가 각 모드 배경 대비
   ≥3:1, fade ≥1.4:1. 색을 바꾸면 게이트가 재계산한다(이 문서의 표를 코드로 옮기는 것).
2. **recede 토큰 단일 원천 테스트** — atlas3d/atlas2d/app.css 의 물러남 값이
   `--recede-*` 한 곳에서 나오는지(숫자 리터럴 grep 0).
3. **스크린샷 계측** — Playwright 로 다크/라이트 × 기본 프레이밍/2단 축소 6컷,
   노드 픽셀의 배경 대비 히스토그램(합격선: 마크 픽셀의 90% 가 3:1 이상 채널에 소속).
4. 기존 규율 회귀 — 모노크롬(색상환 0), 초점 1색, D17 결정론 무변경 확인.
