# Atlas 가시성 연구 심화 검증

> **지위: 연구 입력(research-input).** 채택은 발주자 결정(DEC)으로만 정본화된다.
> 이 문서는 [[vinc.d.atlas-visibility-research]] v0.1 의 후속 검증이며 그 문서를
> 대체하지 않는다. 원문은 진단·제안의 정본으로 남고, 이 문서는 그 위에 측정 기준
> 재판정과 임의 숫자 교체, 신규 제안 R9~R12 를 얹는다.
>
> **적재 주석 (2026-08-02) · 검증 범위의 한계를 먼저 밝힌다.**
> 1. 원문 전문은 이 세션이 `vinc_doc_get` 으로 직접 읽고 대조했다. 따라서 원문의
>    색 hex 와 대비 주장은 원본 그대로다.
> 2. 그러나 심화 검증을 수행한 리서치 실행부는 MCP 스토어와 GitLab 리포에 직접
>    접근하지 못했다. 따라서 **코드 앵커(줄 번호·상수)는 이번에도 검증되지 않았다.**
>    `S=140×spread`, `Fog(pal.fog, S*2.6, S*9)`, `×0.15` 리터럴, `r×0.12`·0.4 월드
>    하한, 8px 문턱, `recede.*` 토큰 실값, sigma 의 `zoomToSizeRatioFunction` 존재
>    여부가 모두 여기 해당한다. 이들은 본문에서 **[스토어 근거]** 로 표시한다.
> 3. 색 hex 로부터 계산되는 값(WCAG 대비비, APCA Lc)은 self-contained 라 독립
>    계산으로 확증했다. 이 부분은 **[계산 확증]** 으로 표시한다.
> 4. 카메라 거리 산술만은 산식으로 검증됐다: `(S·1.1, S·0.9, S·2.1)` 의 원점 거리는
>    `S·√(1.21+0.81+4.41) = S·2.536` 이다. fog near 가 `S·2.6` 이면 기본 프레이밍이
>    fog 시작점 **바로 앞**이라는 원문 주장은 산술적으로 정확하다. **[계산 확증]**

## §0 요약 · 이번 검증이 뒤집은 것

원문의 진단은 살아남았다. 뒤집힌 것은 **측정 기준**과 **임의 숫자 넷**이다.

| # | 판정 | 내용 |
|---|---|---|
| V1 | 확증 | 원문 대비 실측표 13개 항목 전부 WCAG 상대휘도 독립 계산과 일치(오차 ±0.01) |
| V2 | **뒤집힘** | 문제는 값이 아니라 임계다. WCAG 2.x 는 다크 저휘도에서 대비를 과대평가한다. APCA Lc 로 재계산하면 원문이 **유일 합격 채널**로 본 `#6E7189`(4.05:1)조차 solid 최소치 Lc 30 에 미달한다(Lc 28.2) |
| V3 | **뒤집힘** | WCAG 1.4.11 은 전 마크에 3:1 을 강제하지 않는다. 대상은 "내용 이해에 필요한 그래픽 객체"이고 비활성 요소는 면제다. 전 far 노드 일괄 상향은 규범 요구가 아니며 "잉크 총량 불변" 규율과 충돌한다 |
| V4 | **근거 없음** | fade 하한 `1.4:1` 은 문헌 근거가 없다. 대체값은 APCA 불가시 하한 **Lc 15** |
| V5 | **근거 없음** | fog 계수 `×1.5 / ×4.5` 는 임의값이다. 원리(카메라 거리 연동)는 옳으나 `1.5d` 는 타깃 자체를 흐릴 수 있다 |
| V6 | 부분 근거 | `6px` 형태 강등 문턱은 실험 상수가 아니라 보수적 여유값이다. 문헌 하한은 약 0.6mm(표준 밀도에서 2~4 CSS px) |
| V7 | 부분 근거 | `strokeText 2px` 는 두께는 권장 범위 안이나 **헤일로가 아니라 외곽선**이다. 카토그래피 정론은 글자 뒤에 배경색을 깔되 글자 자체를 침해하지 않는 헤일로를 선호한다 |
| V8 | 신규 | 원문이 놓친 최대 후보: **렌더 파이프라인 정합성**(색공간·톤매핑). 여기가 원인이면 팔레트 재보정은 헛수고가 된다 |

## §1 검증표 · WCAG 확증과 APCA 병기 [계산 확증]

배경 다크 `#0C0D13`. APCA 는 0.0.98G-4g 상수 손계산이며 공식 keystone(`#888` 대
`#fff` = 63.06)으로 검산했다. 오차 약 ±0.3 Lc. 다크 배경의 밝은 전경이라 부호는
음수이나 표에는 크기로 적는다.

세부 아이콘·가는 외곽선 최소.

## §2 측정 기준 재판정 · WCAG 게이트 유지, APCA 병기

WCAG 2.x 의 `(L1+0.05)/(L2+0.05)` 는 명도만 보고 폰트 크기·굵기·극성을 무시하며,
한쪽이 near-black 일 때 대비를 과대평가한다. W3C 내부에서도 인정된 한계이고, APCA
문서는 다크에서 4.5:1 이 기능적으로 읽히지 않을 수 있어 WCAG 2.x 를 다크 모드 설계
지침으로 쓸 수 없다고 명시한다.

그러나 거버넌스 현실이 중요하다. **APCA 는 2026-08 기준 규범이 아니다.** 2023-07
WCAG 3 워킹 드래프트에서 제거됐고, 현 초안은 대비 알고리즘을 미정으로 둔다. WCAG 3
규범화 전망은 빨라야 2030 이다. Chromium DevTools 의 APCA 실험 플래그 제거 요청
이슈도 열려 있다.

**권고(무게 높음 · 비용 낮음 · 불변식 위반 없음).**
1. 수용 게이트는 **WCAG 2.x 유지**(비텍스트 3:1, 텍스트 4.5:1). 법적 안전선이고
   결정론 계산이라 백엔드 무LLM 불변식과도 맞는다.
2. 다크 팔레트 설계와 회귀 테스트에는 **APCA Lc 를 병기**해 "3:1 통과, Lc 30 미만"
   함정을 거른다.
3. 두 기준이 충돌하는 다크 저휘도 구간에서는 **더 엄격한 쪽(APCA)** 을 따른다.
   다크 solid fill·stroke 는 최소 Lc 30, 권장 Lc 45.
4. APCA 상수는 번들 인라인 가능하므로 CSP 불변식과 충돌하지 않는다.

## §3 1.4.11 적용 범위 재판정

SC 1.4.11 의 대상은 "내용을 이해하는 데 필요한 그래픽의 부분"이며 essential 예외가
있다. 비활성 컴포넌트는 명시적으로 면제된다.

- **수백 개 마크 전체에 3:1 은 규범 요구가 아니다.** 지식 그래프에서 정보는 개별
  노드 색이 아니라 전체 패턴과 연결이다. 요구되는 최소선은 (a) 상호작용 대상
  (호버·포커스·선택) (b) 구별이 과업상 필수인 채널이다. 전 far 노드 일괄 상향은
  과잉이고 "잉크 총량 증가 금지" 와 충돌한다.
- **의도적 후퇴 채널은 3:1 면제.** hover 비이웃과 fade 엣지는 일시적 비강조 상태로
  비활성 예외 논리에 해당한다. 따라서 원문의 `fade ≥ 1.4:1` 은 근거 없는 임의값이다.
  하한을 둘 목적이 "완전 소멸 방지"이므로 근거 있는 대체는 **APCA Lc 15 floor** 다.
  WCAG 비율로는 다크에서 대략 1.5~1.8:1 부근이나 극성 의존이라 Lc 로 명문화가 정확하다.
- **WCAG 2.2 SC 2.4.11 Focus Appearance** 는 그래프 노드 포커스에도 적용된다.
  이는 후퇴가 아니라 강조 방향이라 잉크 총량 규율과 충돌하지 않는다(초점색 1개 안에서 처리).
- **다크 halation.** 다크가 항상 접근성 우위는 아니다. 난시 인구 비중이 크다는
  광학 소매 데이터 연구(11,624명, 한쪽 눈 이상 유의 난시 47.4%)가 있고, 순백·순흑
  대비에서 글자 번짐이 보고된다. Vinc 가 `#E8E7EF` / `#0C0D13` 을 쓰는 것은 완화에
  유리하다. 자주 인용되는 "50%" 수치는 동료심사 출처가 아니므로 인용하지 말 것.

## §4 임의 숫자 교체

### 4.1 fog 계수 (R1)
`×1.5 / ×4.5` 는 문헌 근거가 없다. 원리(카메라 거리 연동으로 화면상 선명 구간 비율을
줌 불변으로)는 옳다. 다만 near 를 `1.5d` 로 두면 타깃 자체가 fog 안에 들어간다.

- 대체 권고: **k1 = 0.6~0.8**(타깃 앞까지 선명), **k2 = 2.0~2.5**(씬 외곽에서만 소멸).
  정확값은 spread 별 시각 튜닝으로 확정.
- **선형 Fog 유지 권고.** FogExp2 는 현실적이지만 near clear-band 를 못 준다. 타깃
  근방을 반드시 선명히 유지해야 하므로 제어성이 좋은 선형 Fog + 거리 연동이 낫다.
- **fog 제거는 비권고.** 대기 원근은 실제 깊이 단서다. 폐색·운동 시차가 일부 보완하나
  약하게라도 유지하고 티어 명도와 이중으로 깊이를 표현하는 편이 낫다.
- **fog 색을 배경색과 같게 두는 것이 소멸의 직접 원인이다.** three.js 매뉴얼이
  권하는 표준 관행이지만, 배경보다 아주 약간 밝은 fog 색을 쓰면 먼 노드가 안개 속
  실루엣으로 남는다. 잉크 추가가 아니라 기존 채널의 하한 조정이다.
- **갱신 시점은 controls change 이벤트만.** 매 프레임 갱신은 불필요하다.

### 4.2 형태 강등 문턱 (R6)
카토그래피 표준은 인쇄 점 심볼 최소 0.3mm(관찰거리 50cm, 2 arcmin). 디지털 실험은
원·사각·삼각 구별이 약 0.6mm 아래에서 급락한다고 보고한다. 표준 밀도에서 대략
2~4 CSS px 다. **`6px` 는 실험 상수가 아니라 안전마진 포함 공학값**이며, 그 자체로는
방어 가능하다. 다만 DPI·시청거리를 반영하려면 px 이 아니라 **시각(arcmin) 또는 물리
mm** 로 문턱을 정의하는 것이 정확하다.

### 4.3 라벨 헤일로 (R5)
카토그래피 정론은 헤일로가 외곽선보다 가독성에 낫다고 본다. 외곽선은 글자 획을
침해하지만 헤일로는 글자 뒤에 놓이기 때문이다. 권장 두께 1~2px, 색은 배경색.

- `strokeText 2px` 는 두께는 범위 안이나 **외곽선**이다. 개선: 캔버스에서 배경색
  stroke 를 굵게 먼저 그린 뒤 잉크 fill 을 올리는 의사 헤일로로 전환한다.
- 선이 노드 뒤를 지날 때 끊어 보이게 하는 **edge halo** 도 클러터 저감에 유효하다.
- 상시 라벨 수는 절대 상수(상위 8)가 아니라 **뷰포트 픽셀 예산 + 충돌 회피**로 산정.
  지도 렌더러의 라벨 충돌 인덱스가 실증된 패턴이다.
- 스크린 스페이스 라벨은 **신규 의존성 없이** 순수 캔버스 텍스처 + 스프라이트 스케일
  역보정으로 구현 가능하다(troika-three-text 불요).

### 4.4 sigma 형태 3종 (R8) · 실행 가능성 확인
sigma v3 는 프로그램 API 를 재작성했고 기본 노드는 원이다. 형태 추가는 **이미
존재하는 sigma 패키지**(사각·외곽선 계열)와 자체 WebGL 프로그램으로 가능하다.
즉 R8 은 **신규 npm 의존성 없이 실행 가능**하며 무신규라이브러리 불변식과 충돌하지
않는다. `zoomToSizeRatioFunction` 의 현행 버전 존재 여부는 **[스토어 근거]** 로 남는다.

## §5 모노크롬 부호화 용량

색을 뺀 채널의 변별 용량:

| 채널 | 성격 | 신뢰 구별 단계 |
|---|---|---|
| 형태 | 명목 selective, 축소에 취약 | 상시 4종 이하 |
| 명도 | 순서·양적 | 모노크롬 회색조 약 4~5단 |
| 크기 | 양적(Bertin 은 유일한 quantitative 망막 변수로 봄) | 명목 부적합, 3~4단 |
| 질감·패턴 | selective + associative, 명목 적합 | 저색상 디스플레이에서 유효 채널 |
| 방향 | 명목 | 약 4단 |
| 파선 패턴 | 엣지 명목 | 소수 단 |
| 외곽선 유무 · 채움 유무 | 이진 | 각 2단 |

**판정: 노드 5종 + 엣지 6종을 상시 모노크롬으로 구별하는 것은 과부하다.** 형태 4종
으로 노드 5종을 상시 가르기엔 1종이 모자라고, 엣지 6종을 파선·방향만으로 상시 가르면
축소에서 붕괴한다.

**권고: 상시 전부 구별을 포기하고 on-demand 로 전환한다.**
- 상시 화면: 노드는 형태 3종 + 크기(허브 여부)로 대분류만, 엣지는 방향(화살표·테이퍼)
  과 파선 2종 정도만.
- 세부 타입: hover · 선택 · 필터에서 드러낸다.
- 원문의 "형태 4종 이하 유지" 권고는 **타당**하다. 다만 노드 타입이 5종이므로
  형태=타입 닫힌 층을 상시 1:1 로 유지하려면 5번째는 형태 외 채널(외곽선 유무 등)과
  결합하거나 on-demand 로 미뤄야 한다.
- 형태 채널의 지위는 논쟁적이다. Mackinlay 1986 명목 순위에서 형태는 하위권이었고
  2006 개정에서 2위로 상향됐다. Healey 계열은 hue 가 shape·texture 보다 pop-out
  우선순위가 높다고 본다. 즉 형태는 쓸 수 있으나 명도·크기보다 약하고 축소에 먼저
  무너진다. 원문 C5 진단은 지각 문헌과 정합한다.
- 모노크롬 선례(흑백 인쇄 네트워크 도해, 학술 figure, Tufte 계열)는 형태·질감으로
  명목, 명도로 순서, 라벨·범례로 세부를 위임하는 3중화로 통했다.

## §6 원문이 놓친 것 · 신규 제안 R9~R12

### R9 · 렌더 파이프라인 정합성 점검 (무게 높음 · 비용 낮음)
three.js r152 부터 `outputEncoding` 이 `outputColorSpace` 로 대체되고 기본이
`SRGBColorSpace`, `ColorManagement.enabled` 기본 true 가 됐다. `toneMapping` 기본은
r152 에서도 `NoToneMapping` 으로 **바뀌지 않았다.**

따라서 톤매핑이 흑화의 공범이라면 그것은 저작자가 명시적으로 켠 경우다. 그러나
구버전 인코딩 가정이나 명시적 톤매핑이 있으면 **계산상 대비와 실제 화면 대비가
어긋난다.** 저휘도 다크 마크에서 이 어긋남은 치명적이다.

**팔레트를 손대기 전에 이것부터 확인한다.** 확인 항목: `outputColorSpace`,
`toneMapping`, `ColorManagement.enabled`, 팔레트 hex 의 sRGB 일관 해석. 덧붙여
FXAA·MSAA 로 서브픽셀 stroke 소멸을 완화한다. **확인 결과 정상이면 즉시 종료하고
R4 로 넘어간다.**

### R10 · 사용자 대비·극성 조절권 (무게 중 · 비용 중)
고정 팔레트 재보정보다 사용자 개인화가 접근성 정론이다. 로컬 설정으로 대비 강도
슬라이더와 라이트·다크 극성 선택을 제공한다. 결정론·오프라인 유지에 지장 없다.

### R11 · 도메인 가지 기반 번들링·집계 (무게 중 · 비용 높음)
D74 폭발 배치가 계층을 이미 좌표에 실었으므로 hierarchical edge bundling 을 그대로
적용할 소지가 크다(가지 = 번들 경로). **단 주의:** 리터러시 연구는 super-node 와
edge bundling 표현을 일반 사용자가 잘 읽지 못한다고 보고한다. 반대로 map-like 표현은
과업·기억에서 우수하다. 즉 번들링은 조망에는 좋지만 판독에는 학습비용이 든다.
hover 로 원본 복원 경로를 반드시 둔다.

### R12 · APCA Lc 회귀 게이트 (무게 높음 · 비용 낮음)
원문 §4-1 대비 계약 테스트에 APCA 를 더해 **WCAG 2.x + APCA Lc 이중 게이트**로
만든다. "3:1 통과, Lc 30 미만" 회귀를 자동 차단한다. 상수 번들 인라인으로 CSP 준수.

### 부수 검토 · 3D 유지의 근거
3D 노드-링크가 지식 그래프 조망에 우월하다는 강한 실증은 없다. 폐색·깊이 모호성
비용이 크다. 3D 유지는 탐색적 몰입과 공간 기억이라는 제품 의도가 있을 때 근거가
있으며, 순수 판독 효율로는 2D 가 안전하다. 축소 조망에서 semantic zoom 으로 2D·맵류
표현으로 전환하는 쪽을 검토할 가치가 있다.

## §9 한계

- **코드 앵커 미검증.** 이번 검증도 리포에 접근하지 못했다. 원문의 코드 상수·줄 번호는
  여전히 대조되지 않은 상태다. 구현 착수 전 실제 HEAD 와 대조가 필요하다.
- **APCA Lc 는 손계산.** 공식 keystone 으로 검산했고 오차 약 ±0.3 Lc 이나, 정밀값은
  공식 계산기나 `apca-w3` 로 재확인하는 편이 좋다. 다만 임계 근처 항목이 없어
  통과·미달 판정은 뒤집히지 않는다.
- **APCA 는 규범이 아니다.** 법적 수용 기준으로 단독 사용하면 위험하다. 이 문서는
  APCA 를 진단 렌즈로만 쓰고 게이트는 WCAG 2.x 로 유지하도록 권고했다.
- **3D 대 2D, 번들링 판독 비용은 일반 그래프 실험 결과**다. Vinc 특유의 지식 그래프와
  사용자층에 대한 자체 사용성 확인 전까지는 추정이다.
- 제품 불변식 점검: R1~R12 어느 것도 오프라인·결정론·CSP·무신규라이브러리·모노크롬·
  초점색 1개·4-State·em 대시 금지·형태=타입 닫힌 층을 깨지 않는다. 유일한 주의점은
  R2 의 fill 상향이 잉크 총량 규율에 저촉될 수 있다는 것이며, 그래서 fill 상향 대신
  외곽선 승격을 권고했다. 발주자 결정이 필요한 불변식 충돌은 발견되지 않았다.
