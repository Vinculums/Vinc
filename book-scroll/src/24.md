# How Nodes and Edges Become Visible

A Graph is a data structure, but nobody reads database tables directly. People understand structure by looking at the shape of Nodes and the lines drawn between them as Edges.

So visualizing a Graph needs its own grammar.

```text
Node Type
    ↓
Shape

Edge Kind
    ↓
Line Language
```

## Node Kinds Can Map to Shapes

Concept, Record, Decision, Episode, Bridge — each carries a different meaning. Telling them apart on screen needs an explicit mapping between Node Type and Shape.

```text
Concept  → shape A
Record   → shape B
Decision → shape C
Episode  → shape D
Bridge   → shape E
```

What matters here is less the specific shapes chosen and more that a mapping rule exists at all. Shapes can change, but the same Node Type has to keep meaning the same thing.

## Edges Have Kinds Too

Draw every relationship with the same line, and the graph's structural differences disappear. Different relationship kinds can get different visual treatment.

## Direction Is Information

```text
A ─────> B

A <─────> B
```

The first carries direction. The second can express a bidirectional relationship. An arrow, or the direction of a line, isn't decoration — it's part of what the graph means.

## Bridges Are Different From Ordinary Edges

A Bridge plays a different role than a plain Node-to-Node connection. Render Bridges with their own distinct treatment, and users can tell an ordinary direct relationship apart from a special connection that bridges two otherwise separate structures. This matters especially where the graph crosses different Domains.

## A View Is More Than Coordinates

Rendering a Graph needs coordinates. But a View isn't just an object storing coordinates. Its core axes are Scope, Viewpoint, Node Shape, Edge Kind, Coordinates, Density, Time, Focus, Interaction.

So the same Graph can look completely different depending on which Scope and Viewpoint get selected.

## Scope and Viewpoint Stay Separate

Scope decides where you're looking. Viewpoint decides how you're looking.

```text
Scope
= where

Viewpoint
= how
```

Scope is held by navigation history and address; Viewpoint is held separately, as a user preference. So changing the Viewpoint doesn't move the Graph Scope you're looking at.

## There Can Be Several Viewpoints

The current View design gives an important role to viewpoints like 3D, 2D, timeline, and weave. Each answers a different question.

```text
3D
= how does the center relate to what surrounds it?

2D
= how does the same structure look on a plane?

timeline
= how is structure arranged along a time axis?

weave
= how can relationships and topics be bundled together?
```

It's the same Graph, examined through different questions.

## Defining a Grammar and Honoring It Are Different Problems

Defining a visual grammar is one thing; having the actual renderer preserve that grammar is another. You can define a vocabulary of Node shapes and still end up, on screen, with several different Node kinds collapsing into roughly the same shape.

```text
Declared Shape Language
        ↓
Renderer
        ↓
Collapsed Visual Language
```

That risk points at an important principle. A visual language isn't finished just because it's documented. The renderer has to actually implement the same contract.

## View Is the Layer Between Data and Interpretation

If the Graph provides structure, View turns that structure into something a person can explore.

```text
Graph
  ↓
View Model
  ↓
Shape / Edge / Coordinate
  ↓
Viewport
  ↓
Human Interpretation
```

So View is more than screen decoration. Which relationship gets emphasized, and which information fades into the background, shapes how a person ends up interpreting the Graph.
