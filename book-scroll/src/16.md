# How Memory Gets Found

Memory being stored somewhere isn't enough to make it usable for the task in front of you.

When a question comes in, the system first has to find relevant memory. But a search result, by itself, is not an answer.

## Search Isn't One Method

Full-text search is strong at finding an exact word or expression — confirming that a specific phrase actually appears somewhere in a document.

Vector search is strong at finding candidates that are close in meaning even when the wording is different. Even if the question is phrased differently from the source, it can pull in documents or Nodes sitting in the same semantic neighborhood.

The two don't compete. Full-text finds matching wording; vector finds semantic proximity.

But results from either are still just candidates. If several Concepts with similar titles show up in a result set, picking whichever one scored highest isn't automatically safe — different memories can share similar wording.

## Two Lists Become One

Each arm hands back its own ranked list, and the two lists do not share a scale. A full-text score and a distance in vector space are not the same kind of number, so neither can be trusted as an absolute, and adding them would mean nothing.

So the lists are merged by rank rather than by score. A chunk that sits near the top of both lists rises. A chunk only one arm liked sits lower. This is reciprocal rank fusion, and its one setting is how steeply the top of a list is rewarded over the rest. VINC sets it steep on purpose: what goes on to the next stage is the handful both arms put near the top, not everything either of them found.

## A Third Reader, Only When the Two Disagree

Neither arm reads the question and the candidate together. A cross-encoder does: it takes the pair and judges how well the one answers the other. That judgment is better than either arm's, and far more expensive per pair, so it cannot read everything.

VINC runs it only when the two arms disagree about first place. When both put the same chunk at the top there is nothing for a third reader to reorder, and the gate skips it. Measured on a human-written query set, the gate loses nothing: the queries it skips are exactly the ones where reranking would have changed nothing.

Where the third reader earns its cost is across languages. A Korean question against English text is where the two arms disagree most, and where reranking moves results the most. On natural questions in one language it moves them barely at all.

## From Candidate to Target

In VINC's actual retrieval structure, candidates can arrive through more than one path — found directly in a search result, or surfaced through a Node or Record search. A candidate Node comes from two places: a title that shares words with the question, which any of Concept, Record, Decision and Episode can have, and the Concepts the top-ranked chunks mention.

These candidates get pooled under a common standard, and then the system has to identify the actual Graph Node.

The core principle here: when it's ambiguous, don't choose. If two candidates are equally good fits and there's no basis for preferring one, holding off is safer than the system arbitrarily picking one.

This isn't a search-quality problem — it's a memory-identity problem. Pick the wrong Node once, and everything the system explores from there proceeds on the wrong memory as its foundation.

Conversely, once a Node is clearly resolved, it becomes an entry point for exploring memory. From the resolved Node, you can follow connected Records, Episodes, Decisions, Concepts, and expand into the related structure. If needed, you can go all the way back to the original text of a connected document.

So the retrieval flow runs longer than plain search.

```text
Question
→ Search, two arms
→ One fused list
→ Reranked, if the arms disagreed
→ Candidates
→ Resolution
→ One Node
→ Related Nodes / documents
→ Evidence
```

Resolution, in this structure, isn't the step that turns a search result into an answer. It's the step that identifies, among several candidates, which memory the current question is actually pointing at.

A search system finding a sentence with a high similarity score doesn't mean that sentence is the answer to the current question. Search narrows down where memory might be; resolution decides what it is.

## Different Languages Can Still Be the Same Memory

The same memory can be written in one language and asked about in another. For the text, the semantic arm and the third reader carry most of that distance: a Korean question can reach an English chunk that shares no word with it.

Naming a Node is a different matter, and it was measured. Whether the right Node becomes a candidate at all depends on how many of its title's words the question carries, and on which Concepts the top chunks mention. The semantic arm reshuffles which chunks are on top; it does not put a title on the candidate list. So a question in one language against a title in another fails before ranking, not at it, and no amount of reranking reaches a Node that never entered the pool.

That is why the fact that two languages differ is never enough by itself to confirm they're the same memory, and why final identification still needs the Node's structure and relationships.

So the goal of search isn't to generate an answer on the spot. Search narrows the space that needs interpreting; resolution identifies the target of memory within that space. And once memory is identified, the system can follow its relationships and documents to assemble the material the current task actually needs.

At this point search stops being a plain database function and becomes the entrance to a memory system.
