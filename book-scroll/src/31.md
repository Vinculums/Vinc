# The Cost of Changing a Model and Storage Structure

## Embedding Dimension Is a Storage Contract

An embedding vector's dimension isn't just a model property. If storage is built to hold vectors of a particular width, that width becomes a storage contract.

VINC's existing store uses a fixed vector width. So adding an embedding model with a different width isn't a simple configuration change — a model using a different vector width can't just be dropped into the existing structure.

## Changing the Schema and Regenerating Data Are Different Things

One distinction matters here:

```text
Schema migration ≠ Embedding migration
```

Changing the DDL alone doesn't transform existing documents' embeddings into the new semantic space. Even after the storage structure changes, embeddings for existing chunks still need to be regenerated.

The process required looks like this:

```text
existing chunks
    ↓
new embedding model
    ↓
re-embed
    ↓
new vectors
    ↓
rebuild the vector index
    ↓
validate retrieval
```

So the cost of changing a model shouldn't be calculated as just the cost of a schema migration.

## The Actual Cost of Rebuilding

In VINC's measurements, reindexing a few hundred chunks took around 25 seconds. Embedding generation varied far more by model — some models took more than three times longer to re-embed than others.

Scale that up proportionally, and you're looking at hours for thousands of chunks, and half a day or more for tens of thousands.

These numbers are observations from a specific environment, not an absolute baseline for every environment. But one fact is clear:

«Changing an embedding model can become a migration workload, not a configuration change.»

## Implementation Bugs Are Part of the Migration Cost Too

Changing a model affects more than data structure — it also touches things like an embedding worker's branching logic. Problems can surface in places like prefix handling meant to distinguish between models.

Issues like this don't show up in benchmark numbers alone. So migration evaluation has to include:

```text
Schema compatibility
+ Worker compatibility
+ Model registry
+ Re-embedding
+ Index rebuild
+ Retrieval validation
```

In the end, choosing a model isn't a comparison of model performance — it's a comparison of the cost of changing the entire storage and execution path.
