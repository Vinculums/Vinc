# How Graph Space Gets Created

A Graph isn't just Nodes and Edges. Who owns that Graph, what range of data it holds, and who can access it are all part of the Graph too.

VINC expresses this boundary as Space. The key idea is that Space isn't some separate, complicated graph object — it's a boundary determined by ownership scope.

```text
Space
   ↓
Owner
   ↓
Graph Data
```

## Personal Graphs and Team Graphs

VINC can have Personal Graphs and Team Graphs.

```text
Personal
   ↓
one owner

Team
   ↓
team owner / team space
```

What matters is that these aren't just different folders in the same storage. A different Owner means a different memory boundary.

## Space Becomes Part of a Call

When a tool executes, which Space it's operating in has to be clear.

```text
Tool Call
   ↓
space
   ↓
Graph
```

VINC's tool API can take space as an argument; omit it, and the personal Graph is the default. That default exists for convenience. Using a Team Graph requires specifying the right Space explicitly.

## An Address Can Determine Space Too

At the MCP boundary, a Team endpoint can identify the Space by itself. In that case, the URL address decides which Graph you're entering, and the credential proves you're allowed to enter it.

```text
Address
= which Graph

Credential
= is this caller allowed in
```

This distinction matters especially at the MCP boundary.

## Space Is Not Just a Screen Setting

A user picking a Team in the interface can look like a plain UI action. At the system level, though, Space determines the boundary of data access.

```text
Space
  ↓
Search Scope
  ↓
Graph Scope
  ↓
Document Scope
  ↓
Write Scope
```

So Space isn't a UI selection — it's part of the data model and the permission model.

## Owner Isolation

Mixing Graphs across different Owners breaks the reliability of a memory system. So search and graph traversal both have to stay within the same Owner's scope.

```text
Owner A
 └─ Graph A

Owner B
 └─ Graph B
```

A search under Owner A should never surface a Node from Owner B's graph. This isn't only a security concern — it's a retrieval-correctness concern too.

## Team Roles Are Separate From Space

Having access to a Team Graph doesn't mean permission to do everything inside it. A Team can carry roles like viewer, editor, admin. These decide, separately from whether you can enter the Space at all, what you're allowed to do once you're inside it.

```text
Space
  ↓
Membership
  ↓
Role
  ↓
Allowed Operation
```

So authentication, Space, and Role shouldn't get collapsed into one thing.

## Space and Sync

When a Graph exists across multiple devices or environments, Space also shapes the boundary of synchronization. The same Owner's Graph can converge across environments, but Graphs belonging to different Owners should never merge into one sync scope.

## Why a "Who Am I" Surface Is Needed

As the Space model gets richer, a caller needs to know which Graph it's actually accessing. A surface for confirming this reports the Spaces available in the current connection, and the role held in each.

```text
whoami
   ↓
Identity
   ↓
Available Spaces
   ↓
Role
```

This isn't just a convenience. Call a tool without knowing what Space even exists, and you can end up reading or writing against the wrong Graph.

## Balancing Defaults Against Explicitness

Requiring Space to always be stated explicitly would raise safety. But to stay compatible with existing personal connections, VINC chose to keep Personal as the default when Space is omitted.

```text
space omitted
      ↓
personal

space specified
      ↓
specified graph

team endpoint
      ↓
team graph
```

What matters isn't the default existing — it's that the default is clearly defined as part of the system's contract.

## Graph Space Is a Memory Boundary

In the end, Space decides how far a Graph should be treated as one single memory.

```text
Space
 ├─ Owner
 ├─ Nodes
 ├─ Relations
 ├─ Documents
 ├─ Search
 └─ Permissions
```

So a Graph's space isn't just a visible area on a screen. It's a system boundary that decides whose memory it is, what data gets searched together, and who's allowed to change it.

At this point, a Graph can no longer be described by Nodes and Edges alone. A Graph has time, it has evidence, it has shape, it has viewpoints, and it has a Space wrapping the whole thing.
