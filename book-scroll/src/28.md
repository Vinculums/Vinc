# Measurement Needs Conditions

## Numbers Alone Can't Be Compared

Measuring a system doesn't mean you can immediately start collecting numbers. First you have to decide what counts as the same conditions to compare against.

This problem hits search systems especially hard. Even with the same model, results mean different things depending on the query set, the number of candidate documents, the answer set, the language mix, the embedding approach, the hardware.

So measurement starts in this order:

«Fixture → validate conditions → run → measure → compare»

A fixture is the fixed input set used for evaluation — queries and answers, the document set, the language mix, and so on.

VINC's embedding evaluation checks the fixture itself before reading any numbers. It confirms cross-lingual pairs actually exist in the canonical set, checks that cross-lingual queries are actually written in the stated language, and confirms the answers are a subset of the canonical set. Duplicates and counts get checked first too.

Compute a metric before these checks pass, and you get a number — just not an evaluation result.

## Evaluation Conditions Are Part of the Measurement

Say a search model scores 0.67 nDCG. That number alone doesn't tell you whether it beats another experiment's 0.62. Different corpus sizes between the two experiments change how hard retrieval is.

An evaluation corpus with fewer distractor documents can inflate the absolute score. So VINC's embedding evaluation notes when a corpus cap inflates absolute values above what a full real-world corpus would show, and doesn't compare absolute values directly across different measurements.

What can be compared is the difference between models within the same fixture, under the same conditions.

The principle is simple:

«A measurement isn't a number with conditions stripped out — it's a result that includes its conditions.»

## Reproducible Measurement

A good evaluation needs, at minimum, this information preserved:

- which fixture was used
- whether the fixture is valid
- which model was used
- what precision and quantization were used
- what retrieval architecture was used
- what hardware and kernel conditions it ran under
- what metric was computed
- what result came out
- if it failed, why it failed

Without this, a measurement result stays a one-off observation.

In VINC, the point of measurement isn't to produce a number. It's to hold onto the conditions so the same question can be asked again in the next run.
