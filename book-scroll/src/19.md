# How Memory Becomes Material

Finding a memory doesn't mean an Agent can immediately produce an answer.

What an Agent needs is a set of memories connected to a question — and those memories can carry different kinds of evidence and relationships.

That selected, connected set of memory can be called answer material.

```text
Question
   ↓
Search
   ↓
Resolution
   ↓
selected Node
   ↓
context + relations + evidence
   ↓
answer material
```

## Brief Isn't Just Another Name for Search

A tool like `vinc_brief` isn't simply a search that returns a bit more. Its job is to resolve a question down to one Node, and assemble the material needed to understand that Node.

```text
brief
    │
    ├─ search
    ├─ resolve
    └─ node context
```

A tool like this combines several retrieval steps into a single surface.

Search asks "what could be relevant." Brief asks something slightly different: "what memories need to be seen together to understand this question." So returning a single search hit isn't enough — the resolved Node's graph relationships, connected Records, and relevant document excerpts all get pulled in together.

## The Resolved Node Sits at the Center of the Material

Material construction is centered not on the question itself, but on the resolved Node.

```text
Question
   ↓
resolved Node
   ├─ Concept
   ├─ Record
   ├─ Decision
   ├─ relations
   └─ document excerpts
```

This structure makes provenance traceable. You can see why a given sentence was included, which Record or relationship it connects to, and which document it was drawn from.

## Graph and Document Provide Different Information

The graph provides relationships. The document provides the text that serves as evidence. With only the graph, you know the relationships but might lack fine-grained textual support. With only the document, you have text but still have to work out which concept a given sentence relates to.

So building material means connecting the graph and the document. Relationships like MENTIONS are the axis that connects them. If a document mentions a particular Concept, that connection lets you move from Node to document and back from document to related concept.

## More Material Is Not Always Better

Pull in every possible connection while building material, and an Agent's judgment actually gets harder, not easier. So results need a budget.

At VINC's MCP surface, oversized results don't get returned as-is — a shrinker can reduce their size. What matters isn't blind truncation, but preserving the structure a question actually needs within a bounded result.

This isn't just UI optimization. An Agent's usable context is limited too, so the amount and shape of material has a direct effect on call cost and the quality of judgment downstream.

## When Material Is Insufficient, Say So

Brief's purpose isn't to always produce something substantial. There may be no matching Node for a question, too few relationships, or not enough supporting documents. In that case, insufficiency itself becomes the result.

```text
Question
   ↓
Search
   ↓
insufficient evidence
   ↓
insufficient material
```

Hiding this state behind a plausible-sounding fabricated answer runs directly against the point of a memory system.

## Answer Material Is an Intermediate Layer

In this structure, answer material is neither the final answer nor raw data.

```text
raw memory
    ↓
retrieval
    ↓
resolved memory
    ↓
answer material
    ↓
Agent interpretation
    ↓
answer
```

Answer material is the intermediate layer that organizes memory before an Agent has to judge anything. With this layer, an Agent doesn't need to search the whole document set and traverse the graph from scratch every time. Without it, the Agent has to understand the memory system's internals directly and repeatedly call multiple tools.

So a tool like this doesn't turn memory into an answer. It turns memory into material an Agent can actually use.
