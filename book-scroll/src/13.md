# How the Concept System Is Managed

A graph needs Node kinds. But not every concept people use has to become one of them.

Miss this distinction and the schema just keeps growing.

Say a team uses concepts like "search quality," "cost efficiency," "Korean-language performance," "reproducibility." Being important concepts doesn't mean each one needs its own new Node kind.

A Node kind marks a role the system has to handle structurally differently. A concept, on the other hand, marks a range of meaning people work with inside the system. So a single Node kind — Concept — can express a huge range of different concepts.

That's what gives the structure room to grow. New technologies and new research topics can be expressed inside the existing Concept structure without ever touching the database schema.

## The Problem with an Open Concept Space

The same word can carry different meanings, and different names can point at the same thing. Plain string comparison can't reliably tell whether two concepts are the same.

"Embedding," "vector representation," "semantic vector" don't always mean the same thing. In some contexts they point at the same concept. In others they mark different technical scopes entirely.

So the concept system has to live on a different layer from the graph schema.

Schema defines the structure the system has to understand. The concept system expands the space of meaning the system deals in. The two influence each other — if some new, recurring kind of information keeps resisting the existing Node kinds, that's a signal to reconsider the schema. If the existing schema is already sufficient, there's no need to force a new structure just to hold a new concept.

## Concept Shows Where the Line Sits

Concept, as a Node kind, shows this boundary well. It's a Node kind the system recognizes structurally, but the actual title of a Concept isn't limited to any fixed list. So the graph's structure stays reasonably stable while the meaning it holds keeps expanding.

Making concepts still needs a boundary. Turn every noun in every document into a Concept, and the graph grows fast — but meaningful memory and throwaway phrasing become indistinguishable. Restrict it too tightly, and there's no room to express anything new.

So concept extraction isn't just collecting strings. It's judging whether a given expression is worth referencing independently in future work.

## Storing a Name Isn't the Same as Understanding a Meaning

A string becoming a Node's title doesn't mean the system now understands everything that concept means. The actual meaning has to be interpreted alongside a document's context, its connected relationships, its evidence, and its temporal information.

The concept system is therefore broader than the graph. The graph provides a structure for storing and connecting concepts, but it doesn't need to pin down, as a fixed schema, the entire human sense of what concepts exist.

That distinction is what lets VINC keep its structure stable while its meaning keeps expanding.
