# How Causal Relationships Become Space

An Edge in the Graph is never just a connecting line.

Some relationships only express that two Nodes are connected. Others express that one Node has to exist, structurally, before another can. That difference is what lets a graph's causal structure be read spatially.

```text
A ──prerequisite_of──> B
```

What matters in this relationship isn't A and B's actual coordinates. It's the order relationship: A comes before B.

## Chronological Order and Causal Order Are Different

Say two events get recorded like this:

```text
A: 10:00
B: 11:00
```

This alone doesn't let you say A caused B.

```text
A happened before B
```

and

```text
A is required for B
```

are different claims. Two decisions made on the same day, for instance, don't necessarily mean one presupposes the other. Conversely, two decisions made months apart can still need a prerequisite_of relationship recorded between them, if the later one was actually built on the earlier one — that relationship isn't about timing at all.

So the Graph has to store ordinary temporal information and causal relationships separately.

## Causal Relationships Are Read as a Partial Order

Turning causal relationships into space starts with establishing order. Relations like prerequisite_of, derives_from, and inherits_from can be read as the relationships that generate causal order.

```text
A ──prerequisite_of──> B
C ──derives_from─────> B
D ──inherits_from────> C
```

The goal here isn't lining up the whole graph along one straight line. Some Nodes have order between them; others have no direct order relationship at all. This is a Partial Order.

```text
        A
       / \
      B   C
       \ /
        D
```

You can express that A comes before both B and C, and that B and C both come before D. But which of B or C comes first isn't decided by this structure alone.

## Causal Order Comes Before Coordinates

Thinking about spatialization first tends to raise questions like: should A sit at x=10? Should B sit at x=20?

But the question that actually needs deciding first is simpler: does A < B hold at all? Coordinates don't create order — relationships create order.

```text
Relation
   ↓
Order
   ↓
Coordinate
```

Reverse that sequence, and the on-screen layout starts inventing meaning the graph never actually claimed.

## A Causal Cone Is Built From Relationships

Center on a particular Node A, and two regions become visible around it.

```text
             upstream
                ↑
          prerequisite
                │
          ┌─────A─────┐
          │           │
       derives      derives
          │           │
          ↓           ↓
          B           C
                │
                ↓
            downstream
```

A's upstream includes everything that had to precede it for A to hold. A's downstream is what got derived from A, or connects to it as a structural consequence. This region can be read as a Causal Cone.

Don't mistake a Causal Cone for a simple before-and-after window on a time axis. "A existed before B" and "A is a precondition of B" are different relationships, and the Causal Cone follows the second one. So causal structure and the world's time axis can relate to each other, but they're never the same thing.

## No Metric Gets Invented

Computing coordinates between graph Nodes doesn't mean a physical distance now exists between them. These readings have to stay off-limits:

```text
distance(A, B) = semantic truth
```

or

```text
geometric distance = causal strength
```

Coordinates can be a layout value for the View. Relationships express what the Graph means. The two shouldn't be treated as interchangeable.

## Separate Causal Structure From Layout

Spatializing causal order needs two distinct layers.

```text
Graph Semantics
    ↓
Causal Order
    ↓
Layout Constraint
    ↓
Coordinates
    ↓
Renderer
```

A Layout can visualize Causal Order, but the Layout itself must never invent a new causal relationship. This principle matters more, not less, as visualization gets more elaborate.

## Causal Relationships Affect Search Too

Select a particular Node, and its upstream and downstream become explorable.

```text
Selected Node
     ↓
Causal Neighborhood
     ├─ upstream
     └─ downstream
```

This is more powerful than a plain one-hop search. It lets you see, together, what had to precede a concept for it to make sense, and what got derived from it afterward.

## Causal Space Differs From Semantic Space

Embeddings find sentences or Nodes that sit close together in meaning. A causal graph finds structural precedence and derivation.

```text
Semantic Space = meaning similarity
Causal Space = structural order
```

The two complement each other. Two semantically close Nodes aren't guaranteed to be causally connected. Two causally connected Nodes don't need to sit close together in embedding space either.

## Several Meanings Coexist in Space

VINC's View doesn't assume one single coordinate system can explain everything. The coordinates shown on any one screen can be a visual combination of several structures at once.

```text
Topic + Relation + Causal Order + Time + Density
   ↓
View Coordinates
```

That's the core thing separating graph visualization from a plain force-directed layout problem. Space doesn't replace what the Graph means. Space is one projection for reading what the Graph means.
