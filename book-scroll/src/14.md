# What Grammar the System Remembers By

Structure and concepts alone aren't enough for a system to exchange memory reliably.

A person can look at context and paper over a certain amount of error. A system has to know explicitly what kind of Node something is, which fields are required, and which relationships are allowed. That's what the system's grammar does.

Grammar here doesn't just mean a data format. It covers what Node kinds exist, what structure each Node kind has, what Edges exist, which direction each Edge runs in, and which Node kinds are allowed to connect through which relationship.

The Node kinds that matter in VINC are Concept, Episode, Record, Decision, Bridge, and Entity, and each plays a different role. A Concept marks a unit of meaning that gets referenced repeatedly. An Episode marks an event or experience. A Record marks something observed or reported as fact. A Decision marks a choice or judgment made about something.

Relationships have their own fixed grammar too. relates_to expresses a general association. prerequisite_of is a directed precondition relationship. derives_from expresses derivation, inherits_from expresses inheritance, and about marks what a piece of memory concerns.

So getting the relation name right isn't enough on its own. Connecting A to B with prerequisite_of is a different structure from connecting B to A with the same name. Which Node kinds are even allowed to use a given relationship also matters.

## Errors Don't Get Silently Erased

System grammar should never silently strip out errors in the input.

Filling in a missing required value with something made up, quietly ignoring an unrecognized field, storing a bad relationship without any indication that something's wrong — all of these cause problems later, when the system tries to search or interpret what it holds.

So the point of grammar validation isn't to reject data. It's to keep the system's picture of what it knows and doesn't know explicit and clear.

The same principle holds on the read side. If the write path uses a particular Node-and-Edge grammar, the read path has to understand the same structure. A writing system and a reading system that use different grammars can look at the same Graph and interpret different memories out of it.

## Fragment and Graph Are Not the Same Thing

In VINC, a Fragment can be used as the unit for carrying this structure. A Fragment is the format that moves memory's structure between systems. The Graph is the structure where that memory persists.

Keeping the two apart matters. A Fragment is not memory itself. It's a representation for carrying memory between systems.

In the end, grammar doesn't stand in for meaning. Grammar defines what the system reads and writes, and how. Meaning is built out of a Node's content, its relationships, and the documents and evidence behind it.

Grammar is what makes the system extensible. A new Agent or a new client, whatever it is, can connect to the same memory system as long as it understands the same structure.

System grammar, then, is the boundary between memory and the environment that runs on top of it.
